## 2. 필드 구성 및 레이아웃 비교

### 2.1 기본 정보 섹션 — 필드 유무

| 필드(레이블) | 기본 | 수정모드 | 기획 기본 | 기획 수정모드 |
|--------------|------|----------|-----------|----------------|
| 참여 학교명 | ✅ | ✅ 읽기 전용 | ✅ | ✅ 읽기 전용 |
| 지역 | ✅ | ✅ 읽기 전용 | ✅ | ✅ 읽기 전용 |
| 대상 학년 | ✅ | ✅ 읽기 전용 | ✅ | ✅ 읽기 전용 |
| 학급 수 및 전체 인원 | ✅ | ✅ 읽기 전용 | ✅ | ✅ 읽기 전용 |
| 진행 장소 | ✅ | ✅ Input | ✅ | ✅ Input |
| 대기실 여부 및 위치 | ✅ | ✅ Radio+Input | ✅ | ✅ Radio+Input |
| **희망 교육 진행 기간** | ❌ | ❌ | ✅ 단일 행 | ✅ **날짜 선택기(시작~종료), 필수 \*** |
| 식사 제공 여부 및 안내 | ✅ | ✅ Radio+TextArea | ✅ | ✅ Radio+TextArea |
| 담당 교사 | ✅ | ✅ 3× Input | ✅ | ✅ 3× Input, **필수 \*** |

- **기획 시안만** 희망 교육 진행 기간 필드가 있고, 수정 모드에서 날짜 선택기 + 필수(\*) 표시.
- **기획 수정모드**에서만 담당 교사에 필수(\*) 표시.

### 2.2 기본 정보 — 2열 배치(행 쌍) 비교

**기본 (현재 보기)**  
- Descriptions `column={2}` 기준 흐름: 참여 학교명 → 대상 학년 → 진행 장소 → 식사(span2) → 담당 교사(span2) → 지역 → 학급 수 및 전체 인원 → 대기실.  
- 즉, **행 순서**: (참여 학교명, 대상 학년) / (진행 장소, 지역) / (식사, 학급 수) / (담당 교사, 대기실) 등으로 2열 채움.

**수정모드 (현재 수정)**  
- **읽기 전용 먼저**: 참여 학교명, 지역, 대상 학년, 학급 수 및 전체 인원.  
- **수정 가능 이어서**: 진행 장소, 대기실, 식사, 담당 교사.  
- → 보기 모드와 **필드 순서가 다름** (지역/대상 학년/학급 수 위치 이동).

**기획 기본**  
- 1행: 참여 학교명 \| 지역  
- 2행: 대상 학년 \| 학급 수 및 전체 인원  
- 3행: 진행 장소 \| 대기실 여부 및 위치  
- **4행(전체 너비)**: 희망 교육 진행 기간  
- **5행(전체 너비)**: 식사 제공 여부 및 안내  
- **6행(전체 너비)**: 담당 교사  
- → **2열 구간**은 “학교 식별·규모 → 장소·대기실”로 묶고, **기간/식사/담당 교사**는 한 행씩 전체 너비.

**기획 수정모드**  
- 위와 동일한 행 구성.  
- 희망 교육 진행 기간: 날짜 선택기 2개(시작 ~ 종료).  
- 담당 교사: 문의처/Tel/E-mail Input 3개 + 필수(\*) 표시.

### 2.3 강의·교재 정보

- 네 화면 모두 **동일**: 강의 진행 회차, 교재 현황(뱃지), 교재명, 교재 준비 수량.  
- 수정 모드에서도 전부 읽기 전용(현재 명세와 동일).

## 3. 역할별 관점 정리 (persona 기준)

### 3.1 👨‍💼 시니어 PM 관점

| 항목 | 내용 |
|------|------|
| **결정 필요** | 기획 시안(기획 기본/기획 수정)을 정식 스펙으로 채택할지 여부. 채택 시 “희망 교육 진행 기간” 필드 추가 및 API/데이터 모델 확정 필요. |
| **우선순위** | (1) 현재 구현의 보기/수정 필드 순서 불일치 해결 (같은 순서 유지) (2) 기획 시안 반영 시 기간 필드·필수 표시 범위. |
| **리스크** | 기획 시안 반영 시 `SchoolDetailForModal` 확장, 수정 API 스키마·검증 규칙 변경. |

### 3.2 📋 시니어 기획자 관점

| 항목 | 내용 |
|------|------|
| **요구사항 정리** | 기획 기본/수정 시안은 “희망 교육 진행 기간”을 **필수**로 두고, 담당 교사도 수정 모드에서 **필수(\*)** 로 표시. 현재 명세(school-detail-modal-spec, school-detail-basic-edit-mode-spec)에는 기간 필드 없음. |
| **검증** | “수정 클릭 시 같은 필드가 같은 위치에 두고 값만 입력 가능하게 한다”는 시나리오는 **기본/수정모드**에서 미충족(순서 불일치). **기획 시안**은 2열+전체 너비 행으로 배치를 명확히 구분. |
| **예외** | 희망 교육 진행 기간 미입력 시 저장 불가(기획 수정), 담당 교사 필수 여부는 정책 확정 필요. |

### 3.3 🎨 시니어 UX/UI 디자이너 관점

| 항목 | 기본 | 수정모드 | 기획 기본 | 기획 수정모드 |
|------|------|----------|-----------|----------------|
| **필드 순서 일관성** | 보기 시안 순서 1종 | 수정 시 읽기 전용 4개 우선 → **순서 바뀜** | 2열 블록 + 기간/식사/담당 교사 풀폭으로 고정 | 동일 레이아웃, 입력만 전환 |
| **레이아웃** | 2열 균일 | 2열 균일(순서만 상이) | 2열 3행 + 풀폭 3행 | 동일 + 날짜/담당 교사 컨트롤 |
| **필수 표시** | 없음 | 없음 | 없음 | 희망 교육 진행 기간 \*, 담당 교사 \* |
| **권장** | 수정 모드에서도 **보기 모드와 동일한 필드 순서** 유지하면 “같은 테이블이 편집되는” 인상. 기획 시안 채택 시 풀폭 행(기간/식사/담당 교사)으로 정보 그룹화가 더 명확함. |

### 3.4 👨‍💻 시니어 개발자 관점

| 항목 | 내용 |
|------|------|
| **현재 구현** | 보기: `basicInfoItems` (시안 순서). 수정: `basicInfoReadOnlyItems` + `basicInfoEditableItems` → **합친 순서가 보기와 다름**. |
| **수정 제안** | 수정 모드 items를 **보기와 동일한 순서**로 합치기. 예: 참여 학교명, 대상 학년, 진행 장소, 식사, 담당 교사, 지역, 학급 수 및 전체 인원, 대기실 순으로 두고, 각 셀만 읽기 전용 vs Controller(Input/Radio/TextArea)로 분기. |
| **기획 시안 반영 시** | `SchoolDetailForModal`에 `hopeEducationStartDate`, `hopeEducationEndDate`(또는 `hopeEducationPeriod`) 추가, 폼 스키마·Zod 검증, DatePicker 컴포넌트 및 저장 API 스키마 반영. |
