# 산출 내역 상세 — 산정 항목과 산정 기준 상세 필드

기준 화면은 지급조서 **산출 내역서**와 계좌 지급 현황 상세의 **산출 내역 상세**다. 둘 다 `PaymentOrderCalculationBreakdownTable`을 쓰고, 「상세 보기」는 `PaymentOrderCalculationBasisDetailModal`을 연다.

원격 화면의 숫자는 `SettlementFrontendItemResponse.calculationDetail`(`basisJson`)이 정본이다. 값이 없으면 `-`를 보여 주고, 프론트 공식으로 채우지 않는다. `remoteData`가 아닌 목업·디자인 시스템 경로는 이 문서의 대상이 아니다.

최종 확인: 2026-11-01

## 이상 필드 확인

| 필드                                       | 판단                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 거리 산정 업체, 스냅샷 기준 시각           | 기존 교통비 상세에 없다. 2026-10-25 스냅샷 API의 `provider`, `snapshotAt`을 행으로 올린 것이다. 화면에서 제거했다.                                                 |
| 유류 종류                                  | 같은 스냅샷 레이아웃에서 추가됐다. 이전 강사 교통비 표는 「이동 거리 및 유류비」한 칸이었다. 유류 종류는 단가 입력값이라 행은 유지한다.                            |
| 거리 스냅샷                                | 거리·유류·톨게이트가 모두 없을 때만 나오는 미연결 안내 문구다. 평소 산정 행이 아니다.                                                                              |
| 산정 공식, 산정 항목, 산출 과정, 요약 항목 | 2026-10-24 `layout: remote` fallback이다. 항목별 설계 표가 아니라 `calculationDetail`의 표시 문자열을 그대로 뿌린다. 타입 레이아웃이 잡히면 이 표는 열리지 않는다. |
| 강사비 「합계」                            | 2026-08 강사비 상세부터 있던 행이다. 금액은 「강사비 책정」과 같다. 제미나이는 합계 행이 없다.                                                                     |

그 외 숙박·식사·활동·원천징수·학생/강사 교통비 레이아웃의 행 이름은 스냅샷 연동 이전부터 있던 산정 표다.

## 산출 내역 상세 표

항목이 여러 개여도 참여 기관명·강의 진행 일자는 같은 블록에서 한 칸으로 묶인다.

| 열             | 값                                                           |
| -------------- | ------------------------------------------------------------ |
| 참여 기관명    | 정산 기관명                                                  |
| 강의 진행 일자 | 진행일 + 차시. 계좌 지급 현황 상세는 차시를 회차로 바꿔 표시 |
| 산정 항목      | 아래 항목 라벨                                               |
| 항목 설명      | `item.description`. 없으면 `—`                               |
| 정산 금액      | `item.amount`. 음수는 원천징수 색                            |
| 산정 기준 상세 | 상세 보기. 근거가 없으면 「준비 중입니다.」                  |

항목은 `items[]`를 아래 순서로 정렬해 한 줄씩 만든다.

| API `type`       | 산정 항목 라벨 | 상세 레이아웃                                                       |
| ---------------- | -------------- | ------------------------------------------------------------------- |
| `instructor_fee` | 강사비         | 급수 / 특강 / 제미나이                                              |
| `transportation` | 교통비         | 교통비 스냅샷. `basisJson.layout`이 학생·강사 레이아웃이면 그 표    |
| `accommodation`  | 숙박비         | 숙박비 또는 1사1교 숙박비                                           |
| `meal`           | 식사비         | 식사비                                                              |
| `activity`       | 참여자 활동비  | 참여자 활동비                                                       |
| `withholding`    | 원천징수       | 원천징수. 금액이 음수인 다른 type도 이 라벨                         |
| `other`          | 기타           | 전용 상세 없음. `kind`가 강사비로 떨어져 강사비 상세가 열릴 수 있다 |

`basisJson`이 없거나 필수 숫자가 빠지면 상세 보기는 열리지 않는다. 예외는 강사비다. 강사비 행은 책정 기준 제목과 행 금액으로 급수·특강·제미나이 표를 만든다. 강의 시간은 calculationDetail에 없으면 `-`다.

## 산정 기준 상세 필드

모달 제목은 「{이름} 산정 기준 상세」다.

### 강사비 — 1~3급

제목: 강사비 산정 기준 상세. `layout: lectureFeeTier`

| 행          | 내용                                       |
| ----------- | ------------------------------------------ |
| 구분        | `1급 강사비` / `2급 강사비` / `3급 강사비` |
| 강사비 책정 | 책정 금액                                  |
| 강의 시간   | 차시·회차 또는 `N시간`. 없으면 `-`         |
| 합계        | 강사비 책정과 같은 금액                    |

`tier`는 표 행이 아니다. 구분 문구를 고를 때만 쓴다.

### 특강 강사비

제목: 특강 강사비 산정 기준 상세. `layout: lectureFeeSpecial`

행은 급수 강사비와 같다. 구분은 `특강 강사비`.

### 제미나이 강사비

제목: 강사비 산정 기준 상세. `layout: lectureFeeGemini`

| 행          | 내용                               |
| ----------- | ---------------------------------- |
| 구분        | `제미나이 강사비`                  |
| 강의 시간   | 차시·회차 또는 `N시간`. 없으면 `-` |
| 강사비 책정 | 책정 금액                          |

합계 행은 없다. 차시는 백엔드가 준 `sessionOrdinal`만 쓴다.

### 교통비 — 스냅샷

제목: 교통비 산정 기준 상세. `layout: transportSnapshot`

원격 교통비의 기본 표다.

| 행          | 읽는 값                                       | 없을 때 |
| ----------- | --------------------------------------------- | ------- |
| 편도 거리   | `oneWayDistanceKm`                            | `-`     |
| 왕복 거리   | `roundTripDistanceKm`                         | `-`     |
| 유류 종류   | `fuelType`                                    | `-`     |
| 유류비      | `fuelCostWon`                                 | `-`     |
| 톨게이트비  | `tollAmount` 또는 `tollFeeWon`                | `-`     |
| 산출 교통비 | `calculatedTransportAmount`. 없으면 항목 금액 | `-`     |

거리·유류·톨게이트·유류 종류가 모두 없으면 행은 두 개다.

| 행          | 내용                                    |
| ----------- | --------------------------------------- |
| 거리 스냅샷 | `거리 스냅샷 미연결 — 산출 금액만 표시` |
| 산출 교통비 | 항목 금액                               |

`provider`, `snapshotAt`, `fuelPricePerLiter`는 표시하지 않는다. 유류비는 산출 교통비로 바꾸지 않는다.

### 교통비 — 학생 왕복

`layout: transportRoundTrip`. `basisJson`이 이 레이아웃일 때만.

가는 편(출발), 오는 편(귀가) 각각:

| 행         | 내용                      |
| ---------- | ------------------------- |
| 구분       | 구간 구분                 |
| 대중교통비 | 수단, 금액, 영수증 파일명 |

아래에 합계.

### 교통비 — 학생 편도

`layout: transportOneWay`

| 행         | 내용                      |
| ---------- | ------------------------- |
| 구분       | 구간 구분                 |
| 대중교통비 | 수단, 금액, 영수증 파일명 |

### 교통비 — 강사

`layout: transportInstructor`. 제목 본문은 「강사 교통비 산정 기준」.

| 행                  | 내용              |
| ------------------- | ----------------- |
| 구분                | 구분              |
| 이동 거리 및 유류비 | `거리km`와 유류비 |
| 톨게이트비          | 톨게이트비        |
| 합계                | 합계              |

### 숙박비

`layout: lodgingGeneral`. 제목: 숙박비 산정 기준 상세.

1사1교는 `layout: lodging1s1g`. 제목: 1사1교 숙박비 산정 기준 상세. 행은 같다.

| 행       | 내용                |
| -------- | ------------------- |
| 구분     | 구분                |
| 숙박일수 | 일수 문구           |
| 숙박비   | 금액, 영수증 파일명 |
| 합계     | 합계                |

### 식사비

`layout: meal`. 제목: 식사비 산정 기준 상세.

| 행     | 내용                |
| ------ | ------------------- |
| 구분   | 구분                |
| 식사비 | 금액, 영수증 파일명 |
| 합계   | 합계                |

### 참여자 활동비

`layout: activity`. 제목: 참여자 활동비 산정 기준 상세.

| 행            | 내용                |
| ------------- | ------------------- |
| 구분          | 구분                |
| 참여자 활동비 | 금액, 영수증 파일명 |
| 합계          | 합계                |

영수증은 `receiptUrl`이 있을 때만 링크다. 파일명만 있으면 동작하지 않는 버튼으로 남는다.

### 원천징수

`layout: withholding`. 제목: 원천징수 산정 기준 상세.

`basisJson`에 아래 여섯 숫자가 모두 있을 때만 연다. 하나라도 없으면 3.3%로 다시 계산하지 않고 상세를 열지 않는다.

| 행               | 키                                     |
| ---------------- | -------------------------------------- |
| 1일 급여 총액    | `dailySalaryTotalWon`                  |
| 근로소득공제비용 | `earnedIncomeDeductionWon`             |
| 소득세           | `incomeTaxRatePercent`, `incomeTaxWon` |
| 근로소득세액공제 | `earnedIncomeTaxCreditWon`             |
| 원천징수세액     | `withholdingTaxAmountWon`              |

### 표시용 fallback

`layout: remote`. 위 레이아웃으로 못 읽을 때, `formulaText` · `lineLabels` · `formulaLines` · `summaryLabels` · `resultAmount` 중 하나라도 있으면 연다.

| 행        | 조건            |
| --------- | --------------- |
| 산정 공식 | `formulaText`   |
| 산정 항목 | `lineLabels`    |
| 산출 과정 | `formulaLines`  |
| 요약 항목 | `summaryLabels` |
| 산출 금액 | `resultAmount`  |

제목에 `emojiOverride`가 붙을 수 있다. 이 표는 항목별 산정 필드가 아니다.
