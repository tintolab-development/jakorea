## 현재 상황 분석

### 완료된 Phase
- ✅ **Phase 1-3**: 100% 완료 (기반 구조, 프로그램/신청 관리, 매칭/일정 관리)
- ⚠️ **Phase 4**: 정산 관리 기본 UI 완료 (CURRENT_STATUS.md 기준), 고도화 필요
- ⚠️ **Phase 5**: 대시보드 70% 완료 (집계 지표 완료, 최근 활동 미구현)

### 진행 중/미완료 Phase
- 🔄 **Phase 5**: 사용자 화면 기반 UI 개선 (10% - 신청 결과만 완료)
- ❌ **Phase 4 (V4)**: 권한 관리 시스템 (MVP_ROADMAP_V4_DETAILED.md) - 미시작

### 엑셀 데이터 분석 결과
- **ProgramStatistics** 엔티티: 완전히 새로운 엔티티 필요 (참가자 통계)
- **Program** 엔티티: 대량 필드 추가 필요 (사업분야, IPS, 대상 구분, 영문명, 교재명 등)
- **Sponsor** 엔티티: 영문명 필드 추가
- **ProgramRound** 엔티티: 학급수 필드 추가

## 전략 옵션 비교

### 옵션 1: 기존 MVP Phase 완료 후 엑셀 데이터 추가 ❌ 비권장

**접근 방식:**
1. Phase 4 (V4) 권한 관리 시스템 완료
2. Phase 5 사용자 화면 기반 UI 개선 완료
3. 이후 엑셀 데이터 구조 추가

**장점:**
- ✅ 기존 Phase가 완전히 마무리됨
- ✅ 안정적인 기반 위에 확장

**단점:**
- ❌ **데이터 모델이 불완전한 상태로 Phase 진행**
- ❌ **나중에 데이터 구조 변경 시 기존 Phase 코드 대량 수정 필요**
- ❌ **엑셀 데이터가 실제 업무 데이터인데, 이를 반영하지 않고 진행하면 의미 없음**
- ❌ **참가자 통계(ProgramStatistics)가 없으면 대시보드/보고서 기능 구현 불가**

**예상 문제점:**
- Phase 5 대시보드에서 참가자 통계 표시 불가
- 보고서 기능 구현 시 통계 데이터 없음
- 정산 관리에서 참가자 수 기반 계산 불가

### 옵션 2: 지금 MVP 업데이트 (데이터 모델 먼저 확정) ✅ 권장

**단점:**
- ⚠️ 기존 Phase 코드에 필드 추가 작업 필요
- ⚠️ 일시적으로 기존 Phase 완료 지연

**필요 작업:**
1. 타입 정의 업데이트 (`types/domain.ts`)

## 🎯 최종 권장안: 옵션 2 (지금 MVP 업데이트)

### 이유

1. **엑셀 데이터가 실제 업무 데이터**
   - 엑셀 파일의 데이터 구조가 실제로 필요한 데이터 구조
   - 이를 반영하지 않고 Phase를 진행하면 의미 없는 기능 구현

2. **ProgramStatistics 엔티티가 핵심**
   - 참가자 통계 데이터 없이는 대시보드, 보고서, 정산 기능이 불완전
   - Phase 5 대시보드에서 참가자 통계 표시 불가
   - 보고서 기능 구현 시 통계 데이터 필요

3. **데이터 모델 변경은 초기에 하는 것이 최소 비용**
   - 지금은 타입 정의와 Mock 데이터만 수정하면 됨
   - 나중에 수정하면 모든 Phase 코드 수정 필요

4. **기존 Phase 코드 수정이 최소화됨**
   - 타입 정의만 추가하면 기존 코드는 그대로 동작
   - 새 필드는 선택적(optional)으로 추가 가능
   - UI 폼은 필요할 때 추가 가능
