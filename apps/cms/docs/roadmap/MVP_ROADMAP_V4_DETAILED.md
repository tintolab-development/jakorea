#### 4.1.2 권한 체계 정의

**기획 요구사항:**

- 용어/컨셉 정의
  - **교육 진행자(Educator)**: 강사(`INSTRUCTOR`)와 봉사자(`VOLUNTEER`)를 아우르는 상위 개념
    - 중장기적으로 “강사”/“봉사자”를 구분하되, 운영/화면/이력 관점에서는 **교육 진행자 통합 운영**을 전제로 설계
- 권한 타입 정의
  - `ADMIN`: 관리자 (전체 시스템 관리)
  - `INSTRUCTOR`: 강사 (본인 활동 관리)
  - `VOLUNTEER`: 봉사자 (본인 활동 관리, 1365 연계/봉사시간 관리 포함)
  - `STUDENT`: 수강자 (프로그램 신청 및 참여)
- 권한별 역할(Role) 관리
  - 사용자 계정에 권한 할당
  - 권한 변경 프로세스 (관리자만)
- 권한 상속 구조 (필요시)
  - 관리자 > 강사/봉사자 > 수강자 (읽기 권한 기준)

**디자인 요구사항:**

- 권한 표시 UI
  - 사용자 프로필에 권한 표시
  - 권한별 배지/칩 컴포넌트
- 권한 관리 UI (관리자 전용)
  - 사용자 목록에서 권한 표시
  - 권한 변경 드롭다운

**개발 작업:**

- [ ] 권한 타입 정의 (이미 `UserRole` 타입 생성됨)
- [ ] 권한 검증 유틸리티 함수
  - `hasRole(user, role)`: 특정 권한 보유 여부
  - `hasAnyRole(user, roles)`: 여러 권한 중 하나라도 보유 여부
  - `hasAllRoles(user, roles)`: 모든 권한 보유 여부
- [ ] 권한별 접근 제어 훅
  - `useRequireRole(role)`: 특정 권한 필요 훅
  - `useRequireAnyRole(roles)`: 여러 권한 중 하나 필요 훅
- [ ] 권한 표시 컴포넌트
  - `RoleBadge` 컴포넌트
  - 권한별 색상 및 아이콘

**산출물:**

- 권한 검증 유틸리티 함수

#### 4.3.1 강사/봉사자 신청

**기획 요구사항:**

- 강사/봉사자 신청 폼
  - 기본 정보 입력 (이름, 연락처, 지역, 전문분야)
  - 참여이력 입력 (이전 프로그램 참여 여부)
  - 면접 필요 여부 자동 판단
- 신청 접수 및 상태 관리
  - `PENDING`: 신청 접수
  - `INTERVIEW_REQUIRED`: 면접 필요 (참여이력 0개)
  - `INTERVIEW_SCHEDULED`: 면접 일정 확정
  - `INTERVIEW_COMPLETED`: 면접 완료
  - `APPROVED`: 승인 완료
  - `REJECTED`: 반려
- 봉사자(대학생 경제교육 봉사단 등) 특성 반영
  - **강사비 없음, 1365 봉사시간 연계**를 전제로, 봉사자 계정에는 정산 기능 대신 **봉사시간/활동이력 조회 기능** 중심으로 설계
  - 학기(기수) 단위, **지역별 선발 + 2인 1조 순환 배정** 기준(교육 횟수 균등, 파트너 중복 최소화)을 면접/선발 정보에 함께 저장

**디자인 요구사항:**
