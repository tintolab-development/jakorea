# JA Korea 웹 구축 요구사항 명세 (MD 변환본)

---

## 0. 최초 요청 시 프로세스 (참고사항)

### 0.1 학교(교육 신청)
- 가입/로그인
- 프로그램 선택(소개/기간/소요시간/커리큘럼/비고)
- 신청서 작성(템플릿 + 커스터마이징)
- 신청 완료
- 관리자 검토(확정/반려)
- 진행상태 조회

**상태값 예시**
- 신청완료 → 매칭진행 → 매칭완료 → 교재배송준비 → 교재발송완료 → 교육실시 → 만족도제출 → 강의보고서제출

### 0.2 강사(강의~정산)
- 가입/로그인
- 강의 신청
- 매칭/확정
- 일정 확인(캘린더)
- 강의보고서 제출
- 교통비/강사료 자동산출
- 산출내역 확인(수정요청/검토완료)
- 지급조서
- 지급완료
- 교육완료

### 0.3 관리자(운영)
- 교육신청 승인/반려(반려사유 통지)
- 강의신청 승인/마감
- 학교별 강사 매칭(추가배정 포함)
- 교재배송/만족도/보고서 관리
- 정산 검토/지급조서 발부/이체리스트 다운로드
- 실적 데이터 추출

## 1. 시스템 구성

### 1.1 프론트(사용자 웹사이트)
- 가입/로그인 유형: **개인(참여자) / 학교 / 강사** *(봉사자 삭제)*
- 주요 기능:
  - 프로그램 탐색/신청/상태조회/안내
  - 강사 일정/보고서/정산 확인 등

### 1.2 관리자(백오피스)
- 권한 레벨: **최고관리자 / 관리자 / 일반**
- 주요 기능:
  - 프로그램/신청 승인·반려
  - 강사 매칭
  - 교재 배송 상태
  - 강의/보고서 관리
  - 정산/지급조서/다운로드
  - 폼(템플릿) 관리 등

## 2. 역할 및 권한

### 2.1 프론트 사용자 역할 정의
- **개인(참여자)**
  - 프로그램 신청(개인)
  - 신청내역/진행상황 확인
  - 공지사항 및 프로그램 안내 확인
  - 일정 확인
  - 과제 제출
  - 수료증/활동 확인서 발급
- **학교**
  - 프로그램 신청(학교 단위)
  - 신청서/학생명단 업로드
  - 신청내역/진행상황 확인
  - 학교단위 학생 수료증 다운로드
  - 신청 이후 단계에서 학교 정보 공유  
    (강사 대기실, 급식 가능 여부, 대기실 내 취식 가능여부 등)
- **강사**
  - 강의 신청
  - 매칭/일정 확인(캘린더)
  - 강의보고서 제출
  - 강사비/교통비 산출내역 확인
  - 지급조서 확인(가능 시)
- *봉사자의 경우 ‘개인(참여자)’로 통합*

### 2.2 관리자 권한 정의
- **마스터 관리자**
  - 회원/권한(계정 타입 포함) 총괄 관리
  - 웹 페이지 시스템 설정(메뉴 노출, 권한정책, 상태 값 관리 등)
  - 모든 기능 접근 가능  
    (관리자 탈퇴, 사용자 삭제 등의 이슈 대응 가능)
- **관리자**
  - 프로그램 운영 전반(등록/수정/마감/게시)  
    (프로그램 안내, 신청서 양식 관리 등)
  - 신청 승인/반려, 강사 매칭, 교재배송 상태 관리 및 알림 발송
  - 정산 검토/지급조서 생성/다운로드, 이체리스트 다운로드
- **일반**
  - 권한이 부여되지 않은 기본 ‘조회’ 기능만 있는 사용자

**추가 정책**
- 회원정보 및 프로그램 신청서 양식 등의 접근권한은  
  관리자라고 하더라도 **해당 프로그램을 개설한 사람 중심**으로 확인 가능

## 3. 핵심 프로세스

### 3.1 학교 신청 프로세스
1. 회원가입/로그인 *(ID = 이메일)*
2. 프로그램 선택(소개/기간/소요시간/커리큘럼/비고 등)
3. 신청서 작성  
   - 학교명, 주소, 대상 학년, 학급 수, 학급별 인원, 강사 대기장소 등 입력
4. 신청 완료  
   - “신청 되었습니다” 화면 / 카카오 알림 메세지
5. 관리자 검토 및 배칭 → 확정  
   - 결과 카카오/이메일
6. 진행상황 조회  
   - 신청완료, 매칭 중, 매칭 완료, 교재 배송중(배송 조회), 교육 진행, 교육 완료

### 3.2 강사 프로세스(강의 신청~정산)
1. 회원가입/로그인 *(ID=이메일, 휴대폰 본인인증 가능)*
2. 강의(프로그램) 신청
3. 관리자 승인/마감 + 강의 정보 확인  
   - 학교 위치, 학년, 대기실 등
4. 강사 일정 확인(캘린더/목록 전환)
   - 학교측과 협의사항(교육 단원 등) 및 급식 등과 관련된 소통
   - 채팅 구현이 어렵다면 슬랙, 디스코드 등의 툴도 가능
5. 강의보고서 제출
6. 강사비 신청
   - 교통비 실비 영수증 업로드 + 교통비 금액 입력
   - 거리별 추가 수당 및 강사료 산출: 자동
   - 강의 회차별 강사료 자동산출
7. 지급조서 작성/다운로드, 산출내역 확인 → 신청 완료(정산 완료)

### 3.3 상태값(진행상황) — 최소 요구
- 신청(접수) → 매칭 진행중 → 매칭 완료 → 교재 배송 준비중 → 교재 발송 완료 → 교육 실시 → 만족도 조사 제출 → 강의보고서 제출
- (프로그램 성격에 따라 일부 단계는 비활성 가능)

## 4. 기능 요구사항 (Functional Requirements)

- 우선순위: **P1(필수) / P2(개선) / P3(정책결정 필요)**

### A. 공통/기술
#### FR-A03 (P2) 반응형/배율 이슈 개선
- PC/맥 모니터 사이즈가 다른 환경에서 가로 스크롤/배율 문제 재현 후 수정
- 일부 화면에서 가로스크롤이 나타남

### B. 프론트: 가입/로그인
#### FR-B01 (P1) 가입 유형 선택
- 회원가입 시 **개인 / 학교 / 강사** 선택
- 로그인 ID는 미정
  - 휴대폰 또는 간편인증으로 로그인/회원가입이 가능하다면  
    그 방법이 ID를 중복으로 만드는 걸 방지할 수 있을 것도 같습니다.

#### FR-B02 (P1) 약관 및 개인정보 처리 관련 동의 + 마케팅 동의 항목
- 개인정보 수집 이용 목적 등에 대한 안내
- 뉴스레터/홍보 동의 체크(문구 포함), DB 저장

### C. 프론트: 프로그램(탐색/상세/신청)
#### FR-C01 (P1) “신청 참여” 페이지
- 프로그램 리스트 + 상세 진입 + 신청 CTA 제공
- “신청하기” 클릭 시 로그인/회원가입 유도(동선 명확)

#### FR-C02 (P2) 프로그램 상세 정보 구성
- 프로그램 명 / 후원사 / 진행기간 / 신청접수 기간 / 세부내용 / 커리큘럼 / 교육일정 / 문의처(이메일/연락처)
- 해당 프로그램 포스터 / 키비주얼 이미지 등 활용하여  
  프로그램 리스트 페이지에서 이미지 노출되었으면 함.
- *현재 홈페이지 상 신청페이지에 드러나는 모든 정보는 기본적으로 삽입*

#### FR-C03 (P1) 신청서 작성: 템플릿 기반 + 커스터마이징
- 관리자가 업로드한 신청서 양식 작성 및 제출
- 학교의 경우 참여학생 리스트(엑셀) 업로드 기능 필요

#### FR-C04 (P1) 신청 결과/상태 안내
- 신청 완료 화면
- 관리자 확정 결과를 신청내역에서 확인
- 확정 후 안내 문자/이메일 발송
- 확정 안내 문자 발송

### D. 프론트: 학교(신청/진행조회)

#### (화면 구조 - 대시보드)

#### (게시판 목록)
- 공지사항
- 교육 일정
- 커뮤니티 (채팅 기능 부분)
- 만족도 설문
- 수료증/확인서 발급

#### FR-D01 (P2) 진행상황 조회 화면
- 상태값 기반 타임라인(신청 완료/확정/매칭/교재 발송 준비-교재 발송/교육 진행/만족도 조사 등)

### E. 프론트: 강사(마이페이지/일정/보고서/정산)

#### (화면 구조 - 대쉬보드)
- 상단: 신청 접수 상태
- 좌 하단: 캘린더 + 프로그램 일정
- 우 하단: 강사료 신청 현황

#### (게시판 목록)
- 공지사항
- 교육 일정
- 커뮤니티 (채팅 기능 부분)
- 강의보고서

#### FR-E03 (P1) 강의보고서 제출

## 백오피스(관리자): 관리자 권한 / 다운로드 범위 정책

- 다운로드 권한은 관리자에게 부여하되,
  - 접근 범위는 **프로그램 단위 담당자/파트너/보조**로 제한
  - **비소유 프로그램 다운로드**는 **최고관리자 승인 기반 임시 권한 부여**를 통해 허용

### 관리자 권한 구조(명칭/역할)
- 마스터 관리자
- 관리자
  - 프로그램 운영 담당자
  - 프로그램 운영 파트너
  - 프로그램 운영 보조
- 일반 *(Default 값: 가입만 되어있는 상태, 권한부여 0)*

**역할 정의**
- 담당자: 해당 사업 총괄 담당자  
  - 프로그램 개설, 업로드, 해당 프로그램 참여자 다운로드 권한 등 부여  
  - 프로그램 생성 시 자동으로 부여
- 파트너: 해당사업 파트너로 총괄사업 담당자와 공동 진행 내부 직원  
  - 담당자와 기본 기능은 같되 다운로드 등의 기능 제한
- 보조: 모든 업로드/다운로드/삭제 기능 제외, 뷰어 기능만 설정
- *각각의 명칭은 생성해두되 세부 권한부여는 커스터마이징 할 수 있도록 개발*

**권한요청 UX**
- 권한이 없는 사용자가 다운로드/조회 등 선택 시 ‘권한 부여 요청’ 버튼 등으로 알림
- 마스터 로그인 페이지에서 권한부여 요청 알림 노출 적용

## F. 백오피스(관리자): 신청 승인/반려/매칭

#### FR-F00 (P1) 회원 조회
- 참여자 조회/다운로드
  - 프로그램별
- 강사 조회/다운로드
  - 필라별
- 권한별 다운로드 범위 설정
- 조회/다운로드 이력 기록

#### FR-F01 (P1) 교육 신청 내역 (학교)
- 학교 신청 건에 대해 관리자 승인
  - 선정된 학교에는 ‘선정 안내’를,
  - 선정되지 않은 학교에는 ‘미선정 안내’를 발송
  - 타이틀은 ‘신청 결과 안내’이고 내용에서 미선정/선정 여부 공지
- 관리자 승인 후 ‘알림발송’ 버튼 → 문자/이메일 발송
  - 알림 발송 완료된 건은 버튼 색깔 변경 등의 표시
- 신청서 오기재 사항 담당자가 화면에서 바로 수정 가능 구현 필요

#### FR-F01-1 (P1) 교육 신청 내역 (개인)
- 교육 신청 결과 안내
- 신청서 오기재 사항 담당자가 화면에서 바로 수정 가능 구현 필요

#### FR-F02 (P1) 강의 신청 내역
- 강사 신청 승인/마감
- 학교별 강사 매칭 기능
- 모집 기간 종료 후 추가 배정: 관리자가 직접 강사 정보 입력 및 배정 가능

#### FR-F03 (P1) 강의 매칭 현황
- 일자별 학교 교육 일자에 신청된 강의신청 내역 확인
- 캘린더/목록보기 2가지 형태 제공
- 엑셀 다운로드

## G. 백오피스(관리자): 정산/지급

#### FR-G01 (P1) 교통비/강사료 자동 산출

## 7. 비기능 요구사항(NFR) — 보안/개인정보 및 ISMS-P 수준 통제 목표

### 7.0 보안 목표 및 준거
- 「개인정보보호법」 및 「개인정보의 안전성 확보조치 기준」 준수
- 정보통신망을 통한 개인정보/인증정보 송수신 시 필요한 보호조치 준수
- **ISMS-P 통제 수준(인증 요구사항에 준하는 체계)**을 설계 기준으로 삼음  
  - 강화된 인증(MFA)
  - 접근통제
  - 로그/감사
  - 취약점 관리 등 보안 통제 요구사항 명시

### 7.1 인증/로그인 보안(2FA 포함)

#### NFR-SEC-AUT-01 (P1) MFA(2FA) 적용
- 백오피스(마스터/관리자/일반): 로그인 시 항상 MFA 필수(SMS OTP 기본)
- 프론트(사용자): 기본 로그인은 이메일+비밀번호 원칙  
  - 단, 민감행위(개인정보 다운로드/정산/서류 열람 등) 수행 시 Step-Up MFA 적용 가능(정책 기반)

**수용 기준**
- MFA 미완료 시 백오피스 세션 발급 불가
- OTP 유효시간/재전송 제한/실패 횟수 제한/락(잠금) 정책 적용
- OTP 이벤트(발송/성공/실패/잠금) 로그 기록

#### NFR-SEC-AUT-02 (P1) 비인가 접근 통제 및 세션 보호
- 로그인 시도 레이트리밋/쿨다운/잠금
- 이상 징후 탐지(예: 다회 실패) 및 경고/알림 체계 제공
- 세션/쿠키 보안 속성(HttpOnly, Secure, SameSite) 적용 및 세션 만료 정책 적용

#### NFR-SEC-AUT-03 (P1) 비밀번호 정책
- 최소 길이/복잡도/재사용 제한 적용
- 가능 시 유출 비밀번호 차단 기능(선택) 제공

### 7.2 접근통제/권한관리(RBAC + 프로그램 ACL)

#### NFR-SEC-ACC-01 (P1) 최소권한 원칙(Least Privilege)
- 백오피스 ‘일반’ 권한은 조회전용 기본값으로 고정(마스터가 별도 권한 부여 전)
- 관리자도 프로그램 단위 ACL 범위를 벗어난 데이터 접근/다운로드 금지
  - 예외는 요청/승인 기반으로만 허용

#### NFR-SEC-ACC-02 (P1) 서버 사이드 권한 검증 필수
- UI에서 버튼 숨김/비활성화만으로 불충분
- 모든 민감 기능(다운로드/권한변경/승인·반려/정산 확정 등)은 서버(API)에서 권한 검증 강제

**수용 기준**
- 권한 없는 사용자가 API 직접 호출 시에도 403 등으로 차단
- 권한/승인/다운로드 관련 이벤트는 감사 로그에 기록

### 7.3 암호화(전송/저장/키관리)

#### NFR-SEC-ENC-01 (P1) 전송구간 암호화
- 서비스 전체 구간 TLS(HTTPS) 강제(HTTP 차단 또는 HTTPS 강제 리다이렉트)

#### NFR-SEC-ENC-02 (P1) 저장구간 암호화/마스킹
- 고유식별정보, 계좌정보 등 민감정보는 필요 최소 수집
- 저장 시 강력 암호화 및/또는 마스킹 적용

#### NFR-SEC-ENC-03 (P1) 키 관리
- KMS/HSM 수준 키 분리
- 키 접근권한 통제
- 키 회전(rotate) 정책 적용 가능

### 7.4 로그 보관/점검/무결성

#### NFR-SEC-LOG-01 (P1) 접속기록 보관
- 개인정보처리시스템 접속기록 및 주요 이벤트 로그 최소 1년 이상 보관(법/정책에 따라 확장 가능)

#### NFR-SEC-LOG-02 (P1) 위·변조 방지(무결성)
- 로그는 중앙 저장소에 저장 + 접근통제 적용
- 필요 시 해시/서명 기반 무결성 적용 가능(선택)

**필수 감사 로그 이벤트(예시)**
- 로그인/MFA
- 권한 변경(Owner/Partner/Viewer)
- 권한요청·승인/반려
- 다운로드/내보내기
- 정산 확정
- Owner 소유권 이전

### 7.5 취약점/보안 개발(SSDLC)

#### NFR-SEC-DEV-01 (P1) 보안 코딩 및 코드리뷰
- OWASP Top 10 기반 보안 코딩 가이드 및 코드 리뷰 체크리스트 적용

#### NFR-SEC-DEV-02 (P1) 취약점 점검
- SAST/DAST/Dependency Scan 정기 수행
- 릴리즈 전 1회 이상 모의해킹(펜테스트) 수행(프로젝트 범위 내 최소 1회)

#### NFR-SEC-DEV-03 (P1) 비밀정보 관리
- 소스 코드에 API Key/비밀번호 등 비밀정보 포함 금지
- Secret Manager 등으로 관리

### 7.6 인프라 보안(대기업 수준 운영 통제)

#### NFR-SEC-INF-01 (P1) WAF/봇 차단/Rate Limit/DDoS
- WAF 및 레이트리밋(로그인/OTP/다운로드 포함)
- 봇 차단 및 DDoS 대응 적용

#### NFR-SEC-INF-02 (P1) 네트워크 분리 및 DB 직접접근 차단
- 최소 DMZ/APP/DB 분리 수준 네트워크 구성 적용
- DB 직접접근 차단

#### NFR-SEC-INF-03 (P1) 백업/복구/DR
- 백업 주기 및 복구 목표(RPO/RTO) 명시
- 정기 복구 리허설 가능

#### NFR-SEC-INF-04 (P2) SIEM 연동 또는 알림 체계
- 이상 로그인/대량 다운로드/권한 변경 등 이벤트 알림 체계 제공

### 7.7 개인정보 처리 단계별 통제(수집~파기)

#### NFR-PRIV-01 (P1) 최소수집/목적 제한/보유기간 관리
- 수집 목적과 보유기간 명확 고지
- 목적 달성 시 파기/분리보관 가능

#### NFR-PRIV-02 (P1) 파기(삭제) 기능/절차
- 보유기간 만료 시 파기 또는 분리보관 처리 수행
- 파기 로그 기록

#### NFR-PRIV-03 (P1) 위탁/제3자 제공 반영(기능 관점)
- 위탁/제3자 제공 발생 시 접근통제 및 로그 기록 시스템 반영(정책 문구 별도)

#### NFR-PRIV-04 (P1) 처리방침/동의/권리행사 흐름 지원
- 처리방침/동의서 버전 관리 및 동의 기록 저장
- 열람·정정·삭제 등 권리행사 처리 지원

### 7.8 데이터 내보내기(다운로드) 보호 통제 — 마스킹/익명화/대량추출 방지

#### NFR-DATA-01 (P1) 다운로드/내보내기 시 필드 마스킹(기본값)
- 엑셀/CSV/PDF 등 다운로드 시 개인정보 필드 기본 마스킹/부분마스킹/비노출 처리
- 비마스킹 원본 다운로드는 권한요청/승인(마스터) 등 강화 통제 하에서만 허용

**수용 기준**
- 마스킹 적용 여부 다운로드 로그 기록
- 권한 없는 원본 다운로드 시도 차단 + 권한요청 흐름 제공

#### NFR-DATA-02 (P1) 대량 다운로드 통제(행수 제한/분할/쿼터)
- 대량 추출 방지:
  - 최대 행수 제한
  - 분할 다운로드
  - 시간당/일일 쿼터
  - 반복 다운로드 레이트리밋
- 필요 시 다운로드 사유 입력 요구 가능(정책 기반)

#### NFR-REP-01 (P1) 실적/통계 데이터는 익명·집계 기본값
- 개인 식별정보 없이 익명·집계 데이터 제공 기본값
- 개인 단위 원본 필요 시 강화된 권한/승인 및 목적 기록 요구

#### NFR-REP-02 (P2) 소수집단 보호(Small Cell Suppression) 옵션
- 재식별 위험 소수 표본(예: n<5) 자동 숨김/범주 병합/표시 제한 옵션 제공(정책값)

# 별첨 1) 보안/개인정보/준법 요구사항

## 1. 준거 기준(참조)
- 개인정보보호법 및 관련 하위 규정/고시(개인정보의 안전성 확보조치 기준 등)
- 정보통신망을 통한 개인정보/인증정보 송수신 시 암호화 등 보호조치 요구(생활법령정보 등 안내 기준)
- ISMS-P 인증기준 수준의 통제 항목(관리체계/보호대책/처리단계별)
- OWASP Top 10 기반 웹 애플리케이션 보안(접근통제, 암호화 실패, 인젝션, 보안설정 미흡 등)

## 2. 보안 목표 및 위협 모델(요약)
**목표:** 계정 탈취·권한 오남용·개인정보 유출·서비스 마비를 방지하고, 사고 발생 시 추적가능성과 복구 가능성을 확보

- 관리자 계정 탈취(피싱/비밀번호 재사용/OTP 탈취) → 전체 데이터 유출
- 프로그램 권한(ACL) 오설정/과도한 권한 부여 → 타 프로그램 데이터 무단 열람/다운로드
- 다운로드 기능 악용(대량 추출) → 개인정보 침해사고
- 파일 업로드 악성코드/스크립트 주입 → 서버/사용자 감염
- 웹 취약점(접근통제 우회, 인젝션, XSS/CSRF) → 권한 상승/정보 탈취
- 로그 미보관/위변조 → 사고 원인 규명 불가
- 백업/복구 미흡 → 장애·랜섬웨어 발생 시 서비스 중단 장기화

## 3. 필수 시스템 구성요소(구축되어야 하는 ‘시스템적인 부분’)

| 구성요소 | 요구/설명 |
|---|---|
| 인증/계정 | 백오피스 SMS MFA(필수), 휴대폰 번호 변경/재인증 절차, 강사 가입 SMS 인증 |
| SMS 게이트웨이 | OTP 발송/재전송 쿨다운/일일 제한/발송 이력 보관, 장애 시 우회정책 |
| 권한/접근통제 | RBAC(마스터/관리자/일반) + 프로그램 ACL(담당자/파트너/보조), 권한요청/승인 워크플로우 |
| 암호화/키관리 | TLS(HTTPS) 강제, 저장구간 암호화(민감정보), KMS 기반 키 분리/회전 |
| 로그/감사 | 중앙 로그 수집(권한변경/다운로드/승인/정산), 위변조 방지, 보관/점검 프로세스 |
| 보안운영 | WAF/Rate Limit/DDoS, 모니터링/알림(이상 로그인·대량 다운로드), 보안패치/취약점 대응 |
| 보안개발(SSDLC) | SAST/DAST/Dependency Scan, 코드리뷰, 시크릿 관리, 릴리즈 전 점검/펜테스트(권장) |
| 백업/복구 | 정기 백업, 복구 리허설, RPO/RTO 정의, 랜섬웨어 대비(오프라인/불변 백업 권장) |

## 4. 통제항목별 요구사항 & 검증 체크리스트

| 구분 | 요구사항(요약) | 구현 포인트 |
|---|---|---|
| 접근권한 관리 | 계정 발급/변경/말소 절차, 최소권한(일반=조회전용) 적용 | RBAC+ACL 모델, 권한 부여/회수 UI, 만료 권한 |
| 접근통제 | API 단에서 권한검사(우회 불가) | 미들웨어/가드 적용, 관리자 기능 서버 차단 |
| 인증(MFA) | 백오피스 SMS MFA 필수 | OTP 1회성, 유효시간, 재전송 제한, 잠금 정책 |
| 세션/쿠키 | 세션 하이재킹 방지 | HttpOnly/Secure/SameSite, 세션 타임아웃, 재인증 |
| 암호화(전송) | HTTPS 강제 | HSTS 적용, HTTP→HTTPS 리다이렉트 |
| 암호화(저장) | 민감정보 저장 암호화 및 마스킹 | DB/스토리지 암호화, 필드 레벨 암호화(필요 시) |
| 키관리 | 키 분리/회전/권한통제 | KMS, 최소권한, 키 로테이션 |
| 로그/감사 | 권한변경/다운로드/승인/정산 등 감사 로그 수집 | 중앙 로그 저장, 접근통제, 무결성 고려 |
| 접속기록 보관/점검 | 접속기록 1년 이상(조건 시 2년) + 월 1회 이상 점검 | 다운로드 시 사유 확인/기록(정책) |
| 악성코드 업로드 방지 | 업로드 파일 검사/격리 | 허용 확장자 제한, AV 스캔, 저장소 분리 |
| 웹 취약점 방지 | OWASP Top 10 기반 방어 | 접근통제, 인젝션 방지, XSS/CSRF, 보안설정 |
| 의존성 관리 | 오픈소스 취약점 관리 | Dependency scan, 버전 정책 |
| 인프라 보안 | WAF/Rate Limit/DDoS | 로그인/OTP/다운로드 레이트리밋 |
| 네트워크/DB 접근 | DB 직접접근 차단/분리 | 네트워크 분리, 보안그룹 최소화 |
| 백업/복구 | 정기 백업 + 복구 리허설 + RPO/RTO | 불변 백업(권장), 복구 테스트 |
| 재해/재난 대비 | 장애 대응 체계 | 모니터링/알림, 온콜/플레이북(권장) |
| 출력/다운로드 통제 | 대량 다운로드 통제 및 사유 기록 | 다운로드 권한은 ACL 범위 내 + 요청/승인 |
| 파기 | 보유기간 만료 파기/분리보관 | 배치 작업, 파기 로그 |
| 권한요청 워크플로우 | 타 프로그램 다운로드는 마스터 승인 후만 | 요청 사유/기간, 승인 시 임시 권한+만료 |
| Owner 이전 | 소유권 이전은 Owner+마스터만 가능 | 이전 요청/승인 및 자동 Partner 전환 옵션 |

## 5. SMS MFA(OTP) 상세 정책(권장 기본값)
- OTP 유효시간: 3~5분
- 재전송 쿨다운: 최소 60초(정책 조정 가능)
- 일일 발송 제한/계정 잠금: 과도한 요청·실패 시 잠금/추가 확인
- OTP 1회성(재사용 불가), 서버에서 검증/소거
- 휴대폰 번호 변경: 기존 번호 인증 + 신규 번호 인증(또는 마스터 승인) 절차
- SIM Swap(유심 스왑) 리스크 보완: 위험도 높은 작업(대량 다운로드/권한 변경) 시 추가 확인(재인증, 관리자 승인, 알림) 권장
- 감사 로그: OTP 발송/성공/실패/잠금 이벤트 기록

## 6. 프로그램 단위 접근통제(RBAC+ACL)
- 관리자 다운로드는 담당자/파트너 프로그램에 한정
- 타 프로그램 다운로드는 권한요청 → 마스터 승인 → 임시권한(만료) 부여
- 권한 변경/다운로드/승인 모두 감사 로그로 추적

## 7. 테스트/점검

| 항목 | 내용 |
|---|---|
| 권한 테스트 | RBAC(마스터/관리자/일반) × ACL(담당자/파트너/보조/None) 조합으로 다운로드·승인·권한변경·템플릿 접근 검증 |
| 보안 테스트 | MFA 우회 불가, OTP 재사용 불가, 레이트리밋 동작 검증 |
| 취약점 점검 | SAST/DAST/Dependency Scan 결과 제출 + High/Critical 조치 내역 |
| 로그 점검 | 다운로드/권한변경 이벤트 로그 기록, 보관/조회 가능 여부 검증 |
| 복구 테스트 | 백업본으로 복구 리허설 수행, RPO/RTO 충족 여부 확인 |

# 별첨 2) 채팅기능 관련 추가자료 및 강사료 산식

## 1. 채팅에서 주로 다뤄지는 내용
- 대기장소
- 교육 단원 협의
- 점심식사 제공 여부
- 성범죄 동의 서류 학교 양식으로 업데이트 요청  
  *(채팅 샘플 첨부)*

## 2. 댓글 기능 구현 시나리오
- 각 일정별(학교별) 게시판 생성(캘린더형)
- 게시판에는 관리자가 학교별 필수 공지사항 작성
- 게시판 별 댓글을 활용하여 강사와 교사 간 소통 공간 마련
- 게시판 조회/댓글 권한: 관리자가 부여  
  - 해당 교육과 관련된 강사/교사만 열람 가능하면 가장 좋음
- 해당 게시판에서 댓글 기능을 통해 담당 강사(2~4명), 교사가 소통 가능
  - 이미 대표강사가 지정되어 있고 교사와 전화 소통 후 내용을 채팅으로 공유/협의해왔기 때문에,
    교사까지 반드시 들어오지 않아도 큰 문제 없을 수 있음
- (아이디어) 슬랙처럼 각 댓글에 답글(스레드) 기능이 있으면 좋음  
  - 주제별 대화를 독립적으로 운영 가능
- (우려사항) 학교 일정 변경 등 변동 사항 발생 시 즉각 대응이 어려울 수 있음(접근성이 떨어짐)
  - 예: 일정 변경 요청, 성범죄 조회 동의 서류 업데이트, 추가 서류 요청 등
  - 기존 밴드채팅은 알림이 즉시 왔지만, 웹 댓글 기능은 직접 들어가 확인해야 하므로
    강사 간 소통 지연 예상(강사 간 개인 연락처 공유가 없는 상황)
- @ 기능(멘션)으로 언급 시 강사 연락처로 문자가 발송되는 등의 부가 기능 필요 가능성 제기

## 3. 교통비 산출 산식
- 구성: **강사비 + 교통비(주유비 + 통행료) + 숙박비(해당자 일괄 80,000원)**

### 3.1 강사비 지급기준
- 기준: 편도 100km = 파주시청 ↔ 용인시청

| 구분 | 기본 강사료 | 장거리 강사비(편도 100km 이상) |
|---|---:|---:|
| 1차시 | 120,000 | 140,000 |
| 2차시 | 170,000 | 190,000 |
| 3차시 | 220,000 | 240,000 |
| 4차시 | 270,000 | 290,000 |
| 5차시 | 320,000 | 340,000 |
| 6차시 | 370,000 | 390,000 |

### 3.2 교통비 지급 기준
1) 자택 ↔ 학교 간 주유비, 통행비 산출  
2) 통행료는 강사가 직접 숫자 기입 + 증빙자료 업로드(담당자 검토)  
3) 자택과 학교 간 거리 60km 이하인 경우 교통비 미지급
