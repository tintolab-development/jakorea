# Cursor prompt — CMS 게시글 관리 FE mock DB 시드 + API 검증

아래 지시를 **이 백엔드 레포에서 실행**하라. 질문은 기존 시드/엔티티를 찾아도 판단이 안 될 때만 하라. 프론트 레포는 없다. 데이터는 이 프롬프트 하단 `SEED_DATA` JSON이 SSOT다.

시드와 **기존 API 비즈니스 규칙 검증**까지 한 작업으로 끝낸다. 부족한 API(G1–G4)는 시드 검증에 필요하면 **이번 작업에서 구현**하라. G5–G8은 구현하지 말고, 작업 후 보고만 하라.

## Goal

CMS LNB 게시글 관리 3화면이 호출하는 API가 FE mock과 같게 나오도록, local/dev DB에 시드하고 비즈니스 규칙을 맞춰라.

| 화면 | path | 모듈 |
|------|------|------|
| 공지사항 | `/admin/posts/notices` | `notices` |
| FAQ | `/admin/posts/faq` | `faqs` |
| 문의내역 | `/admin/posts/inquiries` | `inquiries` |

완료 조건:

1. 관리자 JWT로 아래 GET이 FE mock 건수를 반환한다.
   - `GET /api/admin/content/notices?page=0&size=500` → **27건**
   - `GET /api/admin/content/faqs?page=0&size=500` → **130건**
   - `GET /api/admin/inquiries?page=0&size=500` → **130건**
2. 대표 행이 아래와 같다.
   - 공지 `notice-admin-1`: 제목 `2025년 1월 정산 신청 기간 및 방법 안내`, `isImportant=true`, `status=published`, `category=정산`, `viewCount=1250`
   - FAQ `faq-admin-1`: `category=회원가입`, `status=임시저장`, `question=봉사시간은 언제 확인 가능한가요?`
   - 문의 id `1`: 제목 `1365 포털에 봉사시간이 아직 안 올라왔어요.`, `status=ANSWERED`, 답변 1건, 문의자 표시명 `서봉사`
3. 시드는 **idempotent**. `seedLabel=posts-fe-mock-v1` 기준 upsert 또는 라벨 삭제 후 insert. 다시 돌려도 복제되지 않는다.
4. `local` (또는 이 레포의 dummy seed profile)에서만 들어간다. prod 마이그레이션에 넣지 마라.
5. 아래 비즈니스 규칙 검증 curl이 통과한다.

## Out of scope / 금지

- Platform 사용자 공지/FAQ/문의 API와 테이블을 섞지 마라. CMS admin API만.
- 프로그램 상세의 진행 게시글(`program posts`)과 섞지 마라.
- 프론트에 bulk create API를 새로 만들지 않아도 된다. **시더/Flyway local**이면 충분하다.
- 공지 첨부 **파일 바이너리**를 만들지 마라. `hasAttachment` boolean(+ 이름 배열)만.
- 엑셀 export(G8), 목록 서버 필터 신규 쿼리(G7), 공지 `updatedAt` 컬럼 추가(G6), 첨부 upload API(G5)는 **이번 작업에서 구현하지 마라**.
- 한글 카테고리명을 영문 enum으로 바꾸지 마라. 값은 JSON 그대로 (`정산`, `회원가입`, `봉사시간`).
- FE `draft`를 `draft`로 저장하지 마라. OpenAPI enum은 `published` | `임시저장` | `archived`.

## 구현 순서

1. 공지/FAQ/문의 엔티티·테이블·카테고리 테이블을 찾아라. OpenAPI 스키마명: `NoticeResponse`, `FaqResponse`, `InquiryResponse`, `InquiryAnswerResponse`, `CategoryRequest`.
2. 기존 local dummy seed / `local` profile / data.sql / Flyway `local` 패턴을 **그대로 재사용**하라. 새 시드 프레임워크를 만들지 마라.
3. 시드 순서:

```text
notice_categories (8) → faq_categories (8) → inquiry_categories (9)
→ notices (27) → faqs (130)
→ member stubs → inquiries (130) → inquiry_answers (ANSWERED만, 32건)
```

4. 문의 카테고리 테이블/API가 없으면 **G1을 이번 작업에서 추가**하라 (`/api/admin/inquiry-categories`, 공지/FAQ 카테고리와 동일 스키마).
5. `InquiryResponse`에 문의자 이름·전화·이메일이 없으면 **G2를 이번 작업에서 추가**하라. 담당자 표시명이 없으면 **G3**.
6. 카테고리 삭제 409·중복명 409·답변된 문의 삭제 409가 없으면 **G4를 이번 작업에서 추가**하라.
7. 목록 쿼리: `page` 0-base. FE는 `size=500`으로 한 번에 가져온다. 배열 또는 `{ items: [] }` / `{ content: [] }` 모두 unwrap 한다.

## 고정 값

- seedLabel: `posts-fe-mock-v1`
- 공지/FAQ id: JSON `id` 문자열 그대로 (`notice-admin-1`, `faq-admin-1`, `notice-result-2` …)
- 문의 id: `suggestedNumericId` (mock `1`~`7` 그대로, `inq-gen-N` → `800000+N`)
- 문의자 member stub: `inquirerMemberId` (`1`→`1001`, `inq-gen-N`→`810000+N`)
- 담당 관리자 stub: JSON `assignedAdminId` (홍길동=10, 김담당=11, 이운영=12, 박지원=13, 운영팀 관리자=20, IT지원팀=21, 관리자=1)
- `programId`: JSON이 `null`이면 DB도 null. `programNameSnapshot`만 저장. 기존 프로그램 이름과 같으면 링크해도 되지만 스냅샷 문자열을 덮어쓰지 마라.

## 필드 매핑

### 공지 `GET /api/admin/content/notices`

| 시드 JSON | API |
|---|---|
| id | id (string) |
| title | title |
| content | content (상세에 필수. 목록에서 omit 가능) |
| category | category (이름 문자열) |
| createdAt | createdAt |
| isImportant | isImportant |
| viewCount | viewCount |
| hasAttachment | hasAttachment |
| author | author |
| status | status (`published` / `임시저장` / `archived`) |

목록 기본 정렬: `isImportant DESC`, 그다음 `createdAt DESC`. 상단 고정 **개수 제한 없음**.

공개 필터: `status=published`. 비공개 필터: `status=임시저장`. (`archived`는 비공개 쪽에 포함돼도 된다. FE는 `published`가 아니면 비공개로 본다.)

상세 GET 시 조회수를 +1 하는 구현이 이미 있으면 유지하고, 시드 직후 **첫 GET 전** 값이 1250이어야 한다. 없으면 mock 값을 그대로 반환하라.

## G1–G4 (시드 검증에 필요 — 이번 작업에서 구현)

기존에 있으면 재사용하고, 없으면 추가하라. OpenAPI에도 반영하라.

### G1 문의 카테고리 CRUD

공지/FAQ와 동일:

- `GET/POST /api/admin/inquiry-categories`
- `PATCH/DELETE /api/admin/inquiry-categories/{categoryId}`
- body: `CategoryRequest` (`categoryName` 또는 `name`, `status`, `displayOrder`)
- 목록 응답: 공지 카테고리와 같은 page/map items (`id`/`categoryId` + `categoryName`/`name`)

권한은 문의 쓰기와 동일하게 맞춰라 (`INQUIRY_WRITE` 또는 기존 문의 권한).

### G2 문의자 embed

`InquiryResponse`에 다음을 추가하라. 상세·목록 모두.

- `inquirerName` (string)
- `inquirerPhone` (string)
- `inquirerEmail` (string)

회원 마스터 join이 가능하면 join하고, 시드 stub만 있으면 JSON 값을 스냅샷으로 저장하라. 빈 값으로 `-`를 보내지 마라. 없으면 필드 omit.

### G3 담당자 표시명

`InquiryResponse.assignedAdminName` (string, nullable). JSON `assignedAdminName`을 시드하라.

### G4 409 규칙

1. 카테고리 DELETE: 그 이름(또는 FK)으로 공지/FAQ/문의가 1건 이상이면 **409**. 본문에 사용 건수를 넣어도 된다.
2. 카테고리 POST/PATCH: 동일 보드 안 이름 중복이면 **409**.
3. 문의 DELETE / bulk-delete: `status=ANSWERED`(또는 답변 1건 이상)이면 **409**. PENDING만 삭제 성공.
4. 답변 POST: 이미 답변이 있으면 409로 막거나, 기존 답변 PATCH만 허용. 답변 1문의 1건.

## 검증

관리자 토큰으로. `$BASE`는 로컬 서버 (예: `http://localhost:8080`).

```bash
TOKEN=...
BASE=http://localhost:8080

# 건수
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/notices?page=0&size=500"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/faqs?page=0&size=500"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/inquiries?page=0&size=500"

# 대표 행
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/notices/notice-admin-1"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/faqs/faq-admin-1"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/inquiries/1"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/inquiries/1/answers"

# 공개 필터
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/notices?page=0&size=500&status=published"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/notices?page=0&size=500&status=%EC%9E%84%EC%8B%9C%EC%A0%80%EC%9E%A5"

# 카테고리
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/notice-categories"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/content/faq-categories"
curl -sS -H "Authorization: Bearer $TOKEN" "$BASE/api/admin/inquiry-categories"

# 글 있는 카테고리 삭제 → 409 (정산 공지가 있음)
# 아래 {id}는 정산 카테고리 id
curl -sS -o /dev/null -w "%{http_code}\n" -X DELETE -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/admin/content/notice-categories/{id}"

# ANSWERED 문의 삭제 → 409
curl -sS -o /dev/null -w "%{http_code}\n" -X DELETE -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/admin/inquiries/1"
```

체크:

- 공지 27 / FAQ 130 / 문의 130
- 공지 목록 선두가 `isImportant=true` 행들
- `notice-admin-1` 필드명 `isImportant` / `viewCount` / `hasAttachment` / `author` (내부 컬럼명을 그대로 노출하지 마라)
- FAQ `faq-admin-1` status가 `임시저장` ( `draft` 가 아님 )
- 문의 1번 `programNameSnapshot` 또는 프로그램명, `inquirerName=서봉사`
- 답변 content에 `1365` 또는 `검토`
- 카테고리 삭제·ANSWERED 삭제 HTTP 409
- 시드 재실행 후 건수가 그대로

PENDING 문의 1건(예: id `2`) DELETE는 200/204 후 목록에서 사라져야 한다. 검증 후 시드를 다시 돌려 복구하라.
