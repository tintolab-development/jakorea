# Cursor prompt — CMS 실적 관리 FE mock 30건 DB 시드

아래 지시를 **이 백엔드 레포에서 실행**하라. 질문은 기존 시드/엔티티를 찾아도 판단이 안 될 때만 하라. 프론트 레포는 없다. 데이터는 이 프롬프트 하단 JSON이 SSOT다.

## Goal

CMS LNB 실적 관리(`/education-records`)가 호출하는 API가 FE mock 30건과 같게 나오도록, 실적 레코드 30건을 **local/dev 시드**로 DB에 넣어라.

완료 조건:

1. 관리자 JWT로 `GET /api/admin/performance-records?page=0&size=50` 가 **30건**을 반환한다.
2. 응답 아이템 필드명은 `PerformanceRecordFrontendResponse` (아래 매핑표의 FE 컬럼)이다. 내부 엔티티 필드명을 그대로 노출하지 마라.
3. id `90001` 행: `educationMonth=2026-12`, `schoolOrOrganizationName=발곡고등학교`, `maleParticipants=15`, `femaleParticipants=12`, `totalParticipants=27`, `title=1사1교 경제금융교육`.
4. 시드는 **idempotent**. 다시 돌려도 30건이 복제되지 않는다 (id 90001~90030 upsert 또는 라벨 `education-records-fe-mock-30-v1` 기준 삭제 후 insert).
5. `local` (또는 이 레포의 dummy seed profile)에서만 들어간다. prod 마이그레이션에 넣지 마라.

## Out of scope / 금지

- Gemini 실적(`training-reports`, `/programs/gemini/performance`, `/api/admin/gemini/...`)과 **테이블·시드·API를 섞지 마라**.
- `POST /api/admin/performance-records/rebuild`로 이 30건을 만들지 마라. rebuild는 프로그램 재집계라 아래 수치가 보장되지 않는다.
- 한글 라벨을 `elementary` / `offline` / `inside_school` 같은 프로그램 도메인 enum으로 **변환하지 마라**. 값은 엑셀 원문 그대로 (초/중/고/대학생/성인, 오프라인/온라인/혼합/온+오프라인, 학교 안/학교 밖, Yes/No).
- 없는 필드를 `"해당없음"` 문자열로 채우지 마라. JSON에 키가 없으면 DB도 null/omit.
- 프론트에 bulk create API를 새로 만들지 않아도 된다. **시더/Flyway local**이면 충분하다.
- 프로그램(program) 30건을 꼭 만들 필요는 없다. `programId` 1~30 FK가 깨지면: (a) 실적만 넣고 FK를 nullable로 두거나 (b) 최소 stub 프로그램을 시드하되, 실적 숫자 컬럼은 이 JSON 값을 덮어쓰지 마라.

## 구현 순서

1. 실적 엔티티/테이블을 찾아라. OpenAPI 내부 스키마명은 `PerformanceRecordResponse`. 컬럼명은 레포 관례를 따르되, JSON 키와 의미가 같아야 한다.
2. 기존 local dummy seed / `local` profile / data.sql / Flyway `local` 패턴을 **그대로 재사용**하라. 새 시드 프레임워크를 만들지 마라.
3. 하단 JSON 30건을 insert/upsert 하라.
4. `GET /api/admin/performance-records` 매퍼가 FE 필드명을 쓰는지 확인하고, 아니면 Frontend DTO 매핑을 고쳐라.
5. `GET /api/admin/performance/summary`가 있으면 이 30건 기준으로 모순 없게 집계되게 하라. 없으면 목록만 시드해도 된다 (FE가 목록으로 피벗함).
6. 목록 쿼리: `page` 0-base, `size` 기본 화면은 50. FE는 배열 또는 `{ content: [] }` 둘 다 unwrap 한다.

## 고정 값

- seedLabel: `education-records-fe-mock-30-v1`
- id: `90001` ~ `90030` (운영 PK 전략과 충돌하면 sequence를 이 구간으로 맞추거나 natural key를 educationMonth+학교+프로그램명으로 잡아라. FE는 목록 `id` 문자열만 있으면 된다.)
- programId: `1` ~ `30` (로컬 안정값)
- performanceStatus: `CONFIRMED` → 목록 API `status`
- revisionNo: `1`
- latestRevisionYn: `true` → 목록 API `latestRevision`
- educationMonth: `YYYY-MM` (`2026-01` … `2026-12`)
- educationHours: **string** (예: `"3"`)

## 검증

관리자 토큰으로:

```bash
curl -sS -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/admin/performance-records?page=0&size=50"
```

체크:

- 아이템 30개
- 90001: 발곡고등학교, 2026-12, 남15 여12 합27
- 필드명이 `sponsorNameKo` / `title` / `district` / `targetLevel` / `maleParticipants` 인지 (`sponsorNamesKo` / `sigungu` / `maleCount` 가 아님)
- 라벨이 `고`, `오프라인`, `학교 안`, `No` 인지
