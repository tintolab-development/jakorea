# CMS 회원 목록 — 이렇게 바꾸려고 합니다 (서버 공유용)

**작성일:** 2026-08-07  
**대상:** 백엔드 · 기획 · 리뷰어  
**상세/계약용 문서:** [member-list-roles-query-redesign-handoff-2026-08-07.md](./member-list-roles-query-redesign-handoff-2026-08-07.md)

이 문서는 **무엇을 왜 바꾸는지**를 사람 읽는 용으로 정리한 것입니다.  
파라미터 이름·OpenAPI·체크리스트는 위 상세 문서를 보시면 됩니다.

---

## 한 줄 요약

지금은 “회원 목록” API 하나에 학교(조직)와 사람이 섞여 있고, 일부 필터는 화면에서 다시 걸러내고 있습니다.  
앞으로는 **학교는 학교 API**, **사람은 회원 API**로 나누고, **누가 목록에 나올지·필터는 전부 서버가 처리**하도록 맞춥니다.

---

## 왜 바꾸나요?

1. **학교는 회원이 아닙니다.** 학교 목록과 사람 목록을 같은 방식으로 다루면 유형·삭제·통계가 헷갈립니다.
2. **강사 / 교사겸강사 / 권한박탈**처럼 역할이 겹치는 경우가 있어, “강사만” 같은 단일 값 필터로는 부족합니다.
3. 화면에서 목록을 한 번 더 걸러내면 **페이지 총 건수·다음 페이지**가 어긋납니다. 필터는 서버가 하는 편이 맞습니다.
4. 목록 탭을 다시 들어올 때 **항상 최신 목록**을 보고 싶습니다 (캐시만 보고 안 부르는 동작은 쓰지 않음).

---

## CMS 화면은 이렇게 보입니다

| 메뉴 | 화면에 보이는 것 | 실제로 불러오는 데이터 |
|------|------------------|------------------------|
| **전체 회원** | 사람 목록 | 학교 **빼고** 모든 사람 (일반, 교사, 강사, 교사겸강사, 강사 권한박탈, 관리자 등) |
| **학교(교사) 회원** | **학교 목록**처럼 보임 | **학교만**. 교사는 이 목록에 안 나옴 |
| └ 학교 상세 → 소속 교사 | 그 학교의 교사 표 | 교사 / 교사겸강사 / **권한박탈된 교사겸강사** 포함 |
| **강사 회원** | 강사 사람 목록 | 일반+강사, 교사+강사. **권한박탈 강사는 안 나옴** |
| **관리자 회원** | 관리자 목록 | 지금과 같이 **관리자 계정 API** 유지 (회원 API로 안 합침) |

쉽게 말해:

- “학교(교사) 회원” 메뉴는 **학교 디렉터리**에 가깝고,
- 그 학교에 소속된 **사람(교사)** 은 학교 안으로 들어가야 보입니다.
- “강사 회원”에는 **활동 가능한 강사**만 두고, 박탈된 사람은 전체 회원·소속 교사 쪽에서 다룹니다.

---

## 역할(roles)을 어떻게 생각할까요?

한 사람은 역할이 **여러 개**일 수 있습니다. 그래서 유형을 하나의 문자열이 아니라 **역할 묶음**으로 봅니다.

예시 (이름은 서버에서 최종 확정):

| 상황 | 역할 묶음 (의미) |
|------|------------------|
| 일반으로만 가입 | 일반 |
| 교사로만 가입 | 교사 |
| 일반이 강사 승인받음 | 일반 + 강사 |
| 교사가 강사 승인받음 | 교사 + 강사 |
| 위에서 강사 권한 박탈 | 일반(또는 교사) + **강사(권한박탈)** |

### 어드민이 강사를 대신 등록할 때

등록 화면에서 **일반 회원 / 교사 회원**을 고릅니다.  
둘 다 “강사로 등록”하는 흐름이라서:

- 일반 선택 → **일반 + 강사**
- 교사 선택 → **교사 + 강사** (교사만 단독 등록이 아님)

“강사만” 단독 유형은 쓰지 않습니다.

### 권한 박탈

- “강사”와 “강사(권한박탈)”은 **동시에 가지지 않습니다.**
- 박탈하면 강사 → 강사(권한박탈)로 **바뀝니다.**

### 목록에 넣을 때 규칙 (exact)

서버는 “강사가 포함되면 전부”가 아니라,  
**역할 묶음이 허용 목록과 정확히 같을 때만** 넣습니다.  
(순서만 다른 건 같은 것으로 봅니다.)

| 목록 | 넣는 사람 |
|------|-----------|
| 전체 회원 | 제한 없음 (단, 학교 조직은 이 API에 없음) |
| 강사 회원 | 일반+강사, 교사+강사만 (**박탈 제외**) |
| 소속 교사 | 교사, 교사+강사, 교사+강사(권한박탈) |

## API는 이렇게 나눕니다

### 1) 학교 목록 — **새로 필요**

- CMS 「학교(교사) 회원」메뉴용
- **학교(기관)만** 내려줌
- 교사·강사 사람 row는 넣지 않음

### 2) 회원 목록 — **개편**

- 사람만 (학교 조직 제외)
- 역할 묶음으로 누구를 넣을지 지정할 수 있어야 함
- 화면 필터(검색, 날짜, 등급 등)도 **쿼리로 받아서** 걸러진 결과·총 건수를 돌려줌

### 3) 소속 교사

- 지금처럼 학교 상세에서 쓰는 API를 이어가도 되고,
- 회원 조회 + “이 학교 소속”으로 맞춰도 됩니다.
- 중요한 건 **권한박탈 교사겸강사도 포함**하는 것

### 4) 관리자

- **지금 쓰는 관리자 계정 API 그대로** 둡니다.
- 회원 목록 API에 관리자만 모으는 방식으로 바꾸지 않습니다.

---

## 페이지마다 쓰는 필터

필터는 화면에서 한 번 더 걸러내지 않고, **조회할 때 서버로 보냅니다.**  
(이름·코드 값은 서버와 맞추면 됩니다.)

### 전체 회원

- 회원명 검색  
- 회원 유형 (사람만 — 학교 조직 옵션은 빼는 방향)  
- 가입 시기 (시작일~종료일)

### 학교(교사) 회원 ← 학교 API

- 기관명 검색  
- 기관 소재지 (시/도, 시/군/구)  
- 등록 시기

### 강사 회원

- 강사명 검색  
- JA 평가 등급: 전체 / A / B / C / D  
- 정산 현황: 지급조서 재신청, 확인 대기 중, 확인 진행 중, 지급조서 확인 완료, 계좌 지급 완료, 해당 없음, 신청 반려, 지급 정정 요청  
- 가입 시기  
- (+ 항상) 활성 강사 역할만 — 권한박탈 제외

### 관리자 회원 ← 관리자 계정 API

- 관리자명 검색  
- 권한 유형: 마스터 / 중간 / 뷰어  
- 가입 시기

### 학교 상세 · 소속 교사

- 목록 위쪽 필터 없음  
- 그 학교 소속 + 교사 관련 역할만 (박탈 포함)

모든 목록: 페이지 번호·페이지 크기

---

## 프론트에서 기대하는 동작

- 메뉴(탭) 들어올 때마다 **목록을 다시 요청**합니다.
- 필터·역할 조건은 요청에 담고, **받은 목록을 그대로** 그립니다.
- 역할 이름·쿼리 이름이 OpenAPI에 정해지면 FE가 맞춥니다.

---

## 서버에 부탁드리는 것 (짧게)

1. **학교 목록 API** 새로 만들기 (사람 제외)  
2. **회원 목록**에서 학교 조직 빼기 + 역할 묶음 필터 + 위 화면 필터  
3. **강사 목록 / 소속 교사**에 넣을 역할 묶음 위 표대로  
4. **권한박탈**을 역할의 한 종류로 둘지(권장)와 토큰 이름 확정  
5. **관리자 탭**은 기존 관리자 API 유지  
6. 정해진 내용을 OpenAPI에 반영해 FE에 공유
