## 🎯 빠른 참조

### 봉사자 운영 특성

- **정산 방식**: 강사비 없음 → 봉사시간으로 관리(1365 연계)
- **운영 단위**: 학기(기수) 단위 운영, 지역별 선발
- **매칭 방식**: 학교 매칭 후 **2인 1조 순환 배정**
- **매칭 기준**: 
  - 개인별 교육 횟수 균등
  - 파트너 중복 최소화
  - 지역 분배 등

### 주요 카테고리 구조

```
홈
진행 프로그램
봉사단
├── 개인정보관리
├── 프로그램관리
│   ├── 수강 프로그램
│   └── 관심 프로그램 관리
└── 봉사단 활동 관리
    ├── 내 봉사 일정
    └── 봉사단 참여 이력
────────────────────
공지사항
FAQ
문의하기
```

### 주요 경로

| 카테고리 | 경로 | 권한 |
|---------|------|------|
| 홈 | `/` | VOLUNTEER |
| 진행 프로그램 | `/programs` | 공유 |
| 봉사 프로그램 | `/volunteers/my/programs` | VOLUNTEER |
| 개인정보 관리 | `/mypage/profile` | 공유 |
| 봉사 이력 관리 | `/histories` | VOLUNTEER |
| 관심 프로그램 | `/programs/favorites` | 공유 |
| 공지사항 | `/notices` | 공유 |
| FAQ | `/posts/faq` | 공유 |
| 문의하기 | `/posts/inquiries` | 공유 |

## 🔑 핵심 원칙

### 브랜치 작업 시

**다른 권한(강사/관리자)에 영향이 갈 것 같으면 기존 컴포넌트를 수정하지 말고 새로운 컴포넌트를 만들어서 진행하세요.**

이 원칙을 따르면:
- 강사/관리자 기능에 대한 부작용(side effect)을 완전히 차단
- 봉사자 전용 기능을 독립적으로 개발
- 코드 리뷰 시 영향 범위를 명확히 파악

### 권한 구분

- **봉사자 전용**: `/volunteers/my/*` 경로 및 봉사자 전용 컴포넌트
- **공유 기능**: 강사/봉사자/수강자가 함께 사용하는 기능
- **강사 전용**: 절대 수정하지 않음
- **관리자 전용**: 절대 수정하지 않음
