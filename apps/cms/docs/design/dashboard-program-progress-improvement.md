# 관리자 메인 홈 - 프로그램 진행현황 표현방식 개선안

**작성 일자**: 2026-01-23  
**작성자**: 기획자 / UX/UI 디자이너 / PM 협의  
**대상**: 관리자(ADMIN) 권한 메인 홈 대시보드

---

## 📋 현재 상태 분석

### 현재 구현

- **위젯**: `ProgramProgressWidget` (program-progress-widget.tsx)
- **표현 방식**:
  - 전체 프로그램 수 (Statistic)
  - 8개 상태별 Progress 바 (수평)
  - 각 상태별 색상 및 개수 표시

### 문제점

1. **가독성**: 8개 상태를 수직으로 나열하여 스크롤 필요
2. **비교 어려움**: 각 상태별 비율을 한눈에 파악하기 어려움
3. **시각적 임팩트 부족**: 단순 Progress 바만으로는 전체 흐름 파악 어려움
4. **상태 간 관계**: 프로그램 라이프사이클의 단계별 흐름이 명확하지 않음

---

## 🎯 개선 목표

1. **한눈에 파악**: 전체 프로그램 진행 현황을 즉시 이해
2. **시각적 명확성**: 상태별 분포와 비율을 직관적으로 표시
3. **단계별 흐름**: 프로그램 라이프사이클 단계를 시각적으로 표현
4. **인터랙티브**: 클릭/호버로 상세 정보 확인 가능

---

## 💡 개선안 제안

### 옵션 1: 파이 차트 + 단계별 타임라인 (추천) ⭐

**구성 요소**:

1. **상단**: 전체 프로그램 수 + 주요 상태 요약 (큰 숫자)
2. **중앙**: 파이 차트 (Pie Chart) - 상태별 분포 시각화
3. **하단**: 단계별 타임라인 (Timeline) - 프로그램 라이프사이클 흐름

**장점**:

- 상태별 비율을 한눈에 파악 가능
- 라이프사이클 단계를 명확히 표현
- 시각적으로 임팩트 있음

**단점**:

- 파이 차트는 상태가 많을 경우(8개) 레이블이 복잡할 수 있음

**라이브러리**: `recharts` (이미 설치됨)

---

### 옵션 2: 도넛 차트 + 상태별 카드 그리드

**구성 요소**:

1. **좌측**: 도넛 차트 (Donut Chart) - 전체 분포
2. **우측**: 상태별 카드 그리드 (2x4 또는 4x2)
   - 각 카드: 상태명, 개수, 비율, 색상 인디케이터

**장점**:

- 도넛 차트 중앙에 전체 수 표시 가능
- 각 상태를 개별 카드로 명확히 표시
- 클릭 가능한 카드로 필터링 가능

**단점**:

- 공간을 많이 차지
- 카드가 많아지면 스크롤 필요

**라이브러리**: `recharts` (이미 설치됨)

---

### 옵션 3: 단계별 진행 바 (Funnel/Waterfall) + 상태별 통계

**구성 요소**:

1. **상단**: 단계별 진행 바 (Funnel 형태)
   - 신청 → 매칭 → 교재 → 교육 → 완료
   - 각 단계별 프로그램 수와 감소율 표시
2. **하단**: 상태별 상세 통계 (Grid)
   - 각 상태별 개수, 비율, 색상 인디케이터

**장점**:

- 프로그램 라이프사이클 흐름을 명확히 표현
- 단계별 이탈률 파악 가능
- 관리자가 즉시 필요한 조치 파악 가능

**단점**:

- Funnel 차트는 recharts에 기본 제공되지 않음 (커스텀 필요)

**라이브러리**: `recharts` (이미 설치됨) + 커스텀 Funnel 컴포넌트

---

### 옵션 4: 트리맵 (Treemap) + 상태별 상세

**구성 요소**:

1. **메인**: 트리맵 (Treemap) - 상태별 면적 비율
2. **우측**: 상태별 상세 정보 (List)
   - 상태명, 개수, 비율, 색상

**장점**:

- 상태별 비율을 면적으로 직관적으로 표현
- 공간 효율적
- 인터랙티브 (호버 시 상세 정보)

**단점**:

- 트리맵은 상태가 많을 경우 복잡할 수 있음
- 작은 면적의 상태는 식별 어려움

**라이브러리**: `recharts` (이미 설치됨)

## 🎨 추천안: 옵션 1 (파이 차트 + 단계별 타임라인)

### 디자인 구성

```
┌─────────────────────────────────────────────────┐
│  전체 프로그램 진행 현황                         │
├─────────────────────────────────────────────────┤
│                                                 │
│  [전체: 45개]                                   │
│                                                 │
│  ┌─────────────────────────────────────────┐  │
│  │         [파이 차트]                      │  │
│  │    상태별 분포 시각화                    │  │
│  │    (8개 상태, 색상 구분)                 │  │
│  └─────────────────────────────────────────┘  │
│                                                 │
│  ┌─────────────────────────────────────────┐  │
│  │  프로그램 라이프사이클 단계              │  │
│  │  ────────────────────────────────────  │  │
│  │  [접수] → [매칭] → [교재] → [교육] → [완료]│  │
│  │   12개    8개     5개     15개    5개   │  │
│  └─────────────────────────────────────────┘  │
│                                                 │
│  [상세 보기 →]                                  │
└─────────────────────────────────────────────────┘
```

### 구현 세부사항

1. **파이 차트 (Pie Chart)**
   - 8개 상태를 색상으로 구분
   - 호버 시 상태명, 개수, 비율 표시
   - 클릭 시 해당 상태로 필터링된 프로그램 목록으로 이동

2. **단계별 타임라인**
   - 프로그램 라이프사이클의 주요 단계 표시
   - 각 단계별 프로그램 수와 비율
   - 진행 중인 단계 강조

3. **인터랙션**
   - 파이 차트 섹션 클릭 → 해당 상태 프로그램 목록
   - 타임라인 단계 클릭 → 해당 단계 프로그램 목록
   - 전체 카드 클릭 → 전체 프로그램 목록

## 🔄 협의 사항

### 1. 기획자 관점

- **질문**: 관리자가 가장 자주 확인하는 정보는 무엇인가?
  - 전체 현황 vs 특정 상태 집중
  - 단계별 진행률 vs 상태별 분포
- **제안**: 두 가지 뷰 모드 제공 (전체 현황 / 단계별 진행)

### 2. 디자이너 관점

- **질문**: 시각적 우선순위는?
  - 파이 차트의 크기와 위치
  - 색상 팔레트 일관성 (기존 statusColors 활용)
- **제안**:
  - 파이 차트는 중앙 배치, 크기 적절히
  - 기존 색상 시스템 유지
  - 반응형 디자인 고려 (모바일에서는 리스트 형태)

### 3. PM 관점

- **질문**: 구현 우선순위는?
  - 옵션 1 (파이 차트) vs 옵션 2 (도넛 차트) vs 옵션 3 (Funnel)
- **제안**:
  - **1단계**: 옵션 1 (파이 차트 + 타임라인) - 빠른 구현
  - **2단계**: 옵션 2 (도넛 차트) - 사용자 피드백 후 개선
