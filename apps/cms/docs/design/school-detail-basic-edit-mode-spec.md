# 학교 상세 정보 모달 — 기본 정보 탭 수정 모드 구현 명세

**대상**: 개발자  
**전달**: 기획·디자인 요구사항을 구현 가능한 단위로 정리한 위임 명세  
**참조**: [persona.md](../../.cursor/rules/process/persona.md), [school-detail-modal-spec.md](./school-detail-modal-spec.md)

---

## 1. 개요

- **범위**: 학교 상세 정보 모달 > **기본 정보** 탭의 **수정 모드**만 구현한다.
- **트리거**: 기본 정보 탭 상단 우측 **수정** 버튼 클릭 시, **수정 가능 필드**만 인풋/라디오/텍스트에어리어로 전환된다. 나머지 필드는 수정 모드에서도 **읽기 전용**으로 유지한다.
- **수정 가능 필드(4개 영역)**: 진행 장소, 대기실 여부 및 위치, 식사 제공 여부 및 안내, 담당 교사.
- **권한**: "학교 담당자(교사) 및 관리자만 작성/수정이 가능합니다" 안내와 일치하도록, 수정 버튼 노출·수정 모드 진입 가능 여부는 **권한 정책**에 따라 제어한다. (1차 구현 시 권한 체크는 mock 또는 항상 true로 두고, UI만 구현해도 무방하다.)

---

## 2. 사용자 시나리오 (기획)

| #   | 시나리오                                                                           | 기대 동작                                                                                                                                  |
| --- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | 사용자가 기본 정보 탭에서 **수정** 버튼을 클릭한다                                 | 수정 가능 4개 영역(진행 장소, 대기실, 식사, 담당 교사)만 인풋/라디오/텍스트에어리어로 전환되고, 나머지는 읽기 전용 텍스트·뱃지로 유지된다. |
| 2   | 수정 모드에서 필드를 변경한 뒤 **저장** 버튼을 클릭한다                            | 유효성 검증 후 API(또는 mock)로 저장 요청하고, 성공 시 수정 모드가 해제되어 읽기 모드로 돌아간다.                                          |
| 3   | 수정 모드에서 **취소**(또는 닫기)를 선택한다                                       | 변경 사항은 반영하지 않고 수정 모드가 해제된다. (확인 다이얼로그는 기획·PM 결정 사항.)                                                     |
| 4   | 수정 모드일 때 **저장** 버튼은 모달 우측 상단(또는 기본 정보 섹션 상단)에 노출한다 | 읽기 모드에서는 "저장" 버튼을 숨기고, 수정 모드에서만 "저장"을 노출한다.                                                                   |

**예외**

- 저장 실패 시: 에러 메시지를 토스트 또는 인라인으로 표시하고, 수정 모드는 유지한다.
- 권한이 없는 사용자: 수정 버튼을 비노출하거나 비활성화한다. (정책 확정 후 적용.)

## 3. 수정 모드에서 컨트롤로 전환되는 영역 (디자인 → 개발)

기본 정보 탭은 **2열 키-값 테이블** 레이아웃을 유지한다. **수정 모드**에서도 **수정 가능 4개 영역**만 인풋/라디오/텍스트에어리어로 치환하고, 그 외는 **읽기 전용** 텍스트·뱃지로 동일하게 표시한다.

### 3.1 섹션 1: 학교 기본 정보

| 필드(레이블)           | 수정 모드                                                             | 데이터 필드                                   | 비고                          |
| ---------------------- | --------------------------------------------------------------------- | --------------------------------------------- | ----------------------------- |
| 참여 학교명            | **읽기 전용** (단일 텍스트)                                           | `schoolName`                                  |                               |
| 지역                   | **읽기 전용** (단일 텍스트)                                           | `region`                                      |                               |
| 대상 학년              | **읽기 전용** (단일 텍스트)                                           | `educationGrade`                              |                               |
| 학급 수 및 전체 인원   | **읽기 전용** ("N개 학급 \| 총 M명")                                  | `classCount`, `studentCount`                  |                               |
| 진행 장소              | **수정 가능** `<Input />` (텍스트)                                    | `venue`                                       |                               |
| 대기실 여부 및 위치    | **수정 가능** 라디오 `있음`/`없음` + (있음 시) 위치 `<Input />`       | `waitingRoomAvailable`, `waitingRoomLocation` | 없음 선택 시 위치 입력 숨김   |
| 식사 제공 여부 및 안내 | **수정 가능** 라디오 `제공`/`미제공` + (제공 시) `<Input.TextArea />` | `mealProvided`, `mealNotice`                  | 미제공 선택 시 안내 입력 숨김 |
| 담당 교사              | **수정 가능** 문의처·Tel·E-mail `<Input />` 3개                       | `teacherName`, `teacherPhone`, `teacherEmail` |                               |

### 3.2 섹션 2: 강의 및 교재 정보 (전부 읽기 전용)

| 필드(레이블)   | 수정 모드                   | 비고            |
| -------------- | --------------------------- | --------------- |
| 강의 진행 회차 | **읽기 전용** (단일 텍스트) | 예: 진행 전     |
| 교재 현황      | **읽기 전용** (뱃지)        | 교재 준비 중 등 |
| 교재명         | **읽기 전용** (단일 텍스트) |                 |
| 교재 준비 수량 | **읽기 전용** ("N권")       |                 |

### 3.3 수정 모드 UI 디테일 (디자이너)

- **레이아웃**: 기존과 동일한 2열 `Descriptions`(또는 동일 스타일 테이블). **값 셀만** 수정 모드에서 위 컨트롤로 교체한다.
- **버튼**: 수정 모드 진입 후 상단에 **저장** 버튼 노출. (기존 "수정" 버튼은 "취소"로 전환하거나, 저장/취소 둘 다 노출 — 팀 합의에 따름.)
- **스타일**: Ant Design `Input`, `Select`, `Radio` 사용. 레이블 배경 `#EDF0F2`(또는 `#fafafa`), 값 셀 배경 `#fff` 유지. 컨트롤은 기존 디자인 시스템(테두리, 높이, 폰트)을 따른다.
- **접근성**: 레이블과 입력 필드 `id`/`aria-label` 연결, 라디오 그룹 `role="radiogroup"` 및 `aria-label` 적용.

## 4. 개발 구현 위임 사항

### 4.1 상태 및 모드 전환

- **모드 상태**: `isBasicEditMode: boolean` (또는 동일 의미의 state)로 읽기/수정 모드 구분.
- **수정** 클릭 → `isBasicEditMode = true`, 폼에 현재 `detail` 값 주입.
- **저장 성공** 또는 **취소** → `isBasicEditMode = false`.

### 4.2 폼 및 검증

- **폼**: **React Hook Form**으로 관리한다. (프로젝트 규칙: 모든 폼은 react-hook-form 사용.) 기본 정보 편집 필드만 하나의 폼으로 묶는다.
- **스키마**: Zod로 **수정 가능 필드만** 검증. 폼에 포함하는 필드: `venue`, `waitingRoomAvailable`, `waitingRoomLocation`, `mealProvided`, `mealNotice`, `teacherName`, `teacherPhone`, `teacherEmail`. 대기실 "있음" 선택 시 `waitingRoomLocation` 필수.
- **제출**: `onSubmit`에서 API(또는 mock) 호출 후 성공 시 모달 부모에 patch 전달 및 모드 해제.

### 4.3 데이터 모델

- 수정 시 patch에는 위 수정 가능 필드만 포함. `SchoolDetailForModal`의 나머지 필드(참여 학교명, 지역, 강의 진행 회차, 교재 현황 등)는 읽기 전용이므로 폼/제출 대상에서 제외.

### 4.4 저장 및 연동

- 1차: **Mock** — 저장 클릭 시 `console.log` 또는 로컬 state 갱신만 수행하고, 수정 모드 해제.
- 2차: **API** — 학교 상세 수정 API가 정해지면 해당 엔드포인트로 PATCH 등 전송 후 성공 시 목록/상세 갱신.

### 4.5 제외 범위 (이번 작업에서 하지 않음)

- **강사진 정보** 테이블의 "수정"·"추가 배정" — 별도 명세로 진행.
- **학생 명단** 탭의 "수정"·"학생 등록" — 별도 명세로 진행.
- 권한에 따른 수정 버튼 노출/비노출 — 정책 확정 후 적용 가능.

## 5. 검증 기준 (Acceptance)

- [ ] 기본 정보 탭에서 **수정** 클릭 시, **진행 장소, 대기실 여부 및 위치, 식사 제공 여부 및 안내, 담당 교사** 4개 영역만 인풋/라디오/텍스트에어리어로 전환된다.
- [ ] 참여 학교명, 지역, 대상 학년, 학급 수 및 전체 인원, 강의 진행 회차, 교재 현황, 교재명, 교재 준비 수량은 수정 모드에서도 **읽기 전용** 텍스트·뱃지로 표시된다.
- [ ] **대기실 여부** "없음" 선택 시 위치 입력이 숨겨진다.
- [ ] **식사 제공** "미제공" 선택 시 안내 입력이 숨겨진다.
- [ ] **저장** 클릭 시 폼 검증 후 (mock 또는 API) 저장이 호출되고, 성공 시 수정 모드가 해제되어 읽기 모드로 복귀한다.
- [ ] **취소** 시 변경 사항 없이 수정 모드가 해제된다.
