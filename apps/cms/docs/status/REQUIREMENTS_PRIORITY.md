# 요구사항 기반 우선순위 (Requirements-Based Priority)

> **기준 문서**: `apps/cms/docs/requirements-specification/requirements.md`  
> **MVP 로드맵**: `apps/cms/docs/requirements-specification/MVP/README.md`  
> 
> **원칙**: 요구사항 명세가 모든 개발 작업의 최우선 기준입니다.

---

## 우선순위 체계

### 기능 우선순위 (요구사항 기준)
- **P0**: 즉시 수정 필요 (버그/이슈)
- **P1**: 필수 기능 (MVP 필수)
- **P2**: 개선 기능 (MVP 이후)
- **P3**: 정책 결정 필요

### MVP 버전 우선순위
1. **v0.1** - 인증/역할/기본 구조 (FR-B01, FR-B02, §2 역할 정의)
2. **v0.2** - 프론트 사용자 핵심 흐름 (FR-C01~C04, FR-D01, FR-E01~E03)
3. **v0.3** - 관리자 운영 기능 (FR-F00~F03, §백오피스 권한)
4. **v0.4** - 정산/지급/실적 (FR-G01, FR-G03, 별첨2 산식)
5. **v0.5** - 보안/컴플라이언스 (NFR-SEC-*, NFR-DATA-*, NFR-PRIV-*)

---

## 현재 상태 vs 요구사항

### ✅ 완료된 항목
- UI 기반 화면 구조 (Phase 5 진행 중)
- Mock 데이터 기반 화면 구현

### ❌ 미구현 핵심 요구사항 (P1)

#### 1. 역할 체계 변경 (v0.1 - 최우선)
- **현재**: `ADMIN / INSTRUCTOR / STUDENT / VOLUNTEER`
- **요구사항**: 
  - 프론트: `개인(참여자) / 학교 / 강사` (봉사자 삭제)
  - 관리자: `마스터 관리자 / 관리자 / 일반`
  - 프로그램 역할: `담당자 / 파트너 / 보조`

#### 2. 회원가입/로그인 (FR-B01, FR-B02 - P1)
- **FR-B01**: 가입 유형 선택 (개인/학교/강사)
- **FR-B02**: 약관/개인정보/마케팅 동의
- **현재**: 로그인만 존재, 회원가입 플로우 없음

#### 3. 상태값 정렬 (v0.1 - P1)
- **요구사항 §3.3**: 8단계 상태값
  ```
  신청(접수) → 매칭 진행중 → 매칭 완료 → 교재 배송 준비중 →
  교재 발송 완료 → 교육 실시 → 만족도 조사 제출 → 강의보고서 제출
  ```
- **현재**: 다른 상태값 체계 사용 중

#### 4. 핵심 프로세스 (v0.2 - P1)
- **FR-C01~C04**: 프로그램 탐색/상세/신청/결과 안내
- **FR-E01~E03**: 강사 마이페이지/일정/보고서
- **FR-D01**: 학교 진행상황 조회 (타임라인)
- **현재**: UI만 존재, 실제 프로세스 미구현

#### 5. 관리자 운영 기능 (v0.3 - P1)
- **FR-F00**: 회원 조회/다운로드 (권한별)
- **FR-F01/FR-F01-1**: 신청 승인/반려 (학교/개인)
- **FR-F02**: 강의 신청 승인/마감/추가배정
- **FR-F03**: 매칭 현황/캘린더/엑셀
- **현재**: UI만 존재, 실제 승인/매칭 로직 미구현

#### 6. 정산/지급 (v0.4 - P1)
- **FR-G01**: 교통비/강사료 자동 산출 (별첨2 산식)
- **FR-G03**: 지급조서/이체리스트 출력
- **현재**: UI만 존재, 실제 산출 로직 미구현

#### 7. 보안/컴플라이언스 (v0.5 - P1)
- **NFR-SEC-AUT-01**: MFA(2FA) 적용 (백오피스 필수)
- **NFR-SEC-ACC-01/02**: RBAC+ACL, 서버 사이드 권한 검증
- **NFR-DATA-01/02**: 다운로드 마스킹/대량 통제
- **NFR-SEC-LOG-01/02**: 감사 로그/무결성
- **현재**: 미구현

## 권장 작업 순서

### Phase 1: Foundation (v0.1) - 최우선
**목표**: 요구사항 기반 역할/상태값/인증 체계 구축

1. **역할 체계 재정의** (Phase 0.1.1)
   - `STUDENT` → `INDIVIDUAL` 마이그레이션
   - `VOLUNTEER` 역할 제거
   - `AdminLevel` (MASTER/ADMIN/GENERAL) 추가
   - `ProgramRole` (OWNER/PARTNER/ASSISTANT) 추가

2. **회원가입 흐름** (Phase 0.1.2)
   - FR-B01: 가입 유형 선택 (개인/학교/강사)
   - FR-B02: 약관/개인정보/마케팅 동의
   - 역할별 추가 정보 입력 폼

3. **로그인 흐름 개선** (Phase 0.1.3)
   - 이메일/비밀번호 로그인
   - 역할 자동 판별 및 리다이렉트

4. **상태값/기본 모델 정의** (Phase 0.1.4)
   - 8단계 상태값 정의 (§3.3)
   - 프로그램/신청서 모델 정렬

5. **네비게이션/라우팅 구조** (Phase 0.1.5)
   - 역할별 메뉴 분리
   - 권한 기반 라우트 가드

### Phase 2: Frontend Core (v0.2) - 다음 우선순위
**목표**: 사용자 핵심 신청/조회 흐름 구현

1. **프로그램 탐색/신청** (FR-C01~C04)
2. **강사 마이페이지/일정/보고서** (FR-E01~E03)
3. **학교 진행상황 조회** (FR-D01)

### Phase 3: Admin Operations (v0.3)
**목표**: 관리자 승인/매칭/상태 운영

1. **회원 조회/다운로드** (FR-F00)
2. **신청 승인/반려** (FR-F01/FR-F01-1)
3. **강의 신청 승인/매칭** (FR-F02/FR-F03)

### Phase 4: Settlement (v0.4)
**목표**: 정산/지급조서 자동화

1. **교통비/강사료 자동 산출** (FR-G01, 별첨2 산식)
2. **지급조서/이체리스트** (FR-G03)

### Phase 5: Security & Compliance (v0.5)
**목표**: ISMS-P 수준 보안/컴플라이언스

1. **MFA/인증 보안** (NFR-SEC-AUT-*)
2. **RBAC+ACL/접근통제** (NFR-SEC-ACC-*)
3. **다운로드 통제** (NFR-DATA-*)
4. **감사 로그** (NFR-SEC-LOG-*)

## Phase 5 (사용자 화면 기반 UI 개선)와의 관계

### 현재 Phase 5 상태
- ✅ 5.1 프로그램 상세 화면 개선 (완료)
- ✅ 5.2 신청 결과 화면 개선 (완료)
- ✅ 5.4 To-do 처리 화면 (완료)
- ✅ 5.5 내 일정 목록 화면 개선 (완료)
- ✅ 5.6 일정 상세 화면 개선 (완료)
- ✅ 5.7 강의 상세 화면 개선 (완료)
- ✅ 5.8 봉사 상세 화면 개선 (완료)
- ✅ 5.9 보고서 작성 화면 (완료)

### Phase 5의 위치
- **Phase 5는 UI 개선 작업**이며, 요구사항의 **기능 구현과는 별개**입니다.
- Phase 5에서 개선한 UI는 **요구사항 기반 기능 구현 시 재활용** 가능합니다.
- **요구사항 기반 기능 구현이 우선**이며, Phase 5는 보조적 역할입니다.
