# CMS — 회원 상세 「관리자 코멘트」

회원 상세 **상세 정보** 탭 상단의 관리자 코멘트 영역(`User.adminComment` 등)에 대한 기획 규칙이다. UI 참고: [`user-detail-admin-comment-section.tsx`](apps/cms/src/features/user/detail/ui/detail-info/user-detail-admin-comment-section.tsx).

## 0. 노출 조건 (CMS 관리자 로그인)

- 로그인 사용자의 `role === 'ADMIN'`(`isCmsAdminUser`)이면 **대상 회원의 권한 승인 현황과 관계없이** 해당 블록을 항상 노출한다. (`shouldShowAdminCommentSectionForViewer`)
- 저장·인라인 편집 가능 여부는 `admin-provisioned-member-cms.md` §2·§3의 기존 규칙을 따르되, **보기**만 필요한 경우에도 블록은 숨기지 않는다.

## 1. 열람 범위 (공통 노출)

- 관리자 코멘트는 **작성자에게만 보이는 개인 메모가 아니다.**
- **CMS에 접근 가능한 모든 관리자**에게 **동일한 내용**으로 노출·열람된다. (역할·팀 구분 없이 회원 단위로 공유되는 운영 메모로 취급한다.)
- 예: **김틴토** 관리자가 작성한 코멘트도 **박다람** 관리자가 회원 상세를 열면 **같이 열람**할 수 있다.

## 2. 빈 상태 문구

- 본문이 없거나 공백만 있으면 **`작성된 코멘트가 없습니다.`** 를 표시한다. (프로그램 내 학교 상세의 동일 영역과 문구 통일.)

## 3. 구현·API 시 유의

- 프론트는 “내가 쓴 것만 조회” 같은 필터를 두지 않는다. 회원 상세 조회 응답에 포함된 `adminComment`(또는 동등 필드)를 그대로 표시한다.
- 백엔드에서 관리자별로 다른 본문을 내려주면 안 된다. **회원당 단일 코멘트(또는 단일 이력의 최신 본문)** 모델과 맞춘다.
- 향후 “작성자 표시”“감사 로그”를 넣더라도, **열람 권한은 전 관리자 공통** 원칙을 유지하는지 기획과 합의 후 반영한다.
