# 전략 결정 문서 - V2 vs V3 개발 전략

**작성 일자**: 2024-12-19  
**결정 일자**: 2024-12-19  
**상태**: ✅ 결정 완료 (하이브리드 방식 - V2 먼저 진행)

---

## 📋 결정 배경

V2와 V3 로드맵 중 어떤 방식으로 개발을 진행할지에 대한 전략 결정이 필요했습니다.

- **V2**: 사용자 화면 기반 UI 개선 중심 (Phase 5)
- **V3**: 인터뷰 내용 반영 + 사용자 화면 기반 UI 개선 (Phase 5-11)

---

## 👥 롤별 의견

### 👨‍💻 시니어 프론트엔드 엔지니어 (개발자)

**의견: V2 먼저 개발 후 V3 마이그레이션**

**이유:**
1. **기술적 리스크 최소화**
   - V2는 사용자 화면 기반 UI 개선으로 범위가 명확하고, 기존 구조를 확장하는 형태
   - 기술적 복잡도가 낮아 안정적으로 진행 가능

2. **점진적 개선**
   - Phase 5(사용자 화면 기반 UI)를 먼저 완료하면 공통 UI 원칙과 컴포넌트 패턴을 확립
   - 이후 V3의 신규 기능에 일관된 패턴 적용 가능

3. **코드 품질**
   - V2 완료 후 리팩토링과 패턴 정리 가능
   - V3에서 재사용 가능한 컴포넌트와 훅 확보

4. **의존성 관리**
   - V3의 Phase 6-11은 V2의 Phase 5에서 확립한 UI 원칙과 컴포넌트를 활용 가능
   - 단계적 의존성 구축으로 복잡도 관리

5. **마이그레이션 비용**
   - V2 완료 후 V3로 전환 시 기존 코드 재사용 가능
   - 변경 범위가 명확해져 리스크 감소

**우려사항:**
- V3를 바로 시작하면 인터뷰 요구사항이 불완전해 변경 가능성이 높음
- V2 완료 후 V3로 전환하면 변경 범위가 명확해짐

---

### 🎨 UX/UI 디자이너

**의견: V2 먼저 개발 후 V3 마이그레이션**

**이유:**
1. **디자인 시스템 확립**
   - V2 Phase 5에서 사용자 화면 기반 UI 원칙(상태 표시, CTA, 안내 문구)을 정립
   - 이후 V3에 일관된 디자인 시스템 적용 가능

2. **사용자 경험 일관성**
   - V2에서 확립한 UX 패턴을 V3 신규 기능에 재사용
   - 전체 시스템의 일관된 사용자 경험 제공

3. **디자인 검증**
   - V2에서 사용자 피드백을 받아 패턴을 개선
   - 검증된 패턴을 V3에 반영

4. **컴포넌트 라이브러리**
   - V2에서 공통 컴포넌트를 확립하면 V3에서 빠르게 적용 가능
   - 디자인 작업 효율성 향상

5. **시각적 일관성**
   - V2 완료 후 전체 디자인 시스템을 정리
   - V3에서 일관된 시각적 언어 적용 가능

**우려사항:**
- V3를 바로 시작하면 인터뷰 기반 요구사항이 불완전해 디자인 변경 가능성 높음
- V2 완료 후 V3로 전환하면 디자인 변경 범위가 명확해짐

---

### 📋 기획자

**의견: V3 기반으로 지금 화면에서 마이그레이션**

**이유:**
1. **비즈니스 우선순위**
   - 인터뷰에서 확인한 Phase 6-11(공문, 정산 고도화, 증빙 등)이 실제 업무에 더 중요
   - 사용자 화면 기반 UI 개선보다 실무 기능이 우선

2. **요구사항 반영**
   - 인터뷰 내용을 즉시 반영해 클라이언트 요구를 빠르게 충족
   - 실무진의 니즈를 빠르게 해결

3. **MVP 범위 명확화**
   - V3가 전체 범위를 포함하므로 V2를 거치지 않고 V3로 바로 진행하는 것이 효율적
   - 중복 작업 방지

4. **변경 최소화**
   - V2 완료 후 V3로 전환하면 변경 범위가 커질 수 있음
   - V3를 바로 시작하면 변경 범위 최소화

5. **실무 연동**
   - 인터뷰 기반 기능(정산 고도화, 공문 관리 등)이 실무에 더 시급
   - 사용자 화면 기반 UI 개선은 나중에 진행해도 무방

**우려사항:**
- V2의 사용자 화면 기반 UI 개선(Phase 5)이 V3에도 포함되어 있어 중복 가능
- V3를 바로 시작하면 인터뷰 요구사항이 불완전할 수 있으나, 1월 미팅에서 보완 가능

**대안 제시:**
- V3의 Phase 5(사용자 화면 기반 UI)는 우선순위를 낮추고, Phase 6-11(인터뷰 기반)을 먼저 진행
- Phase 5는 V3의 다른 Phase 완료 후 진행

---

### 👨‍💼 PM (프로젝트 매니저)

**의견: V2 먼저 개발 후 V3 마이그레이션 (조건부)**

**이유:**
1. **리스크 관리**
   - V2는 범위가 명확하고 기술적 리스크가 낮아 일정 예측이 쉬움
   - 단계적 진행으로 리스크 분산

2. **점진적 검증**
   - V2 완료 후 클라이언트 피드백을 받아 V3에 반영
   - 조기 검증으로 품질 향상

3. **팀 역량**
   - V2 완료로 팀이 시스템에 익숙해진 상태에서 V3 진행이 효율적
   - 학습 곡선 완만화

4. **일정 관리**
   - V2 완료 후 V3로 전환 시점을 명확히 설정 가능
   - 마일스톤 관리 용이

5. **변경 관리**
   - V2 완료 후 V3로 전환하면 변경 범위가 명확해져 관리 용이
   - 변경 요청 대응 효율성 향상

**조건:**
- V2의 Phase 5(사용자 화면 기반 UI)는 우선순위를 조정해 핵심만 먼저 진행
- V3의 Phase 4(정산 고도화)는 최우선이므로 V2 완료 전에도 병행 검토 가능
- 1월 미팅에서 인터뷰 요구사항을 보완한 뒤 V3 범위를 최종 확정

**대안 제시:**
- 하이브리드 접근: V2의 Phase 5 핵심만 먼저 진행하고, V3의 Phase 6-11(인터뷰 기반)을 병행
- V2와 V3의 중복 부분(Phase 5)은 V3 기준으로 통합 진행

## ✅ 최종 결정: 하이브리드 방식 (V2 먼저 진행)

### 결정 내용

**V2 먼저 진행하되, 하이브리드 방식으로 접근**

1. **V2의 Phase 5(사용자 화면 기반 UI) 핵심만 먼저 진행**
   - 우선순위가 높은 화면만 선별하여 진행
   - 공통 UI 원칙과 컴포넌트 패턴 확립에 집중

2. **V3의 Phase 6-11(인터뷰 기반) 병행 검토**
   - 1월 미팅 전까지 요구사항 정리 및 설계 준비
   - 미팅 후 범위 최종 확정

3. **V3의 Phase 4(정산 고도화) 최우선 진행**
   - V2 완료 전에도 병행 검토 및 설계 진행
   - 인터뷰 내용 기반으로 우선 개발

4. **1월 미팅 후 V3 범위 최종 확정**
   - 인터뷰 요구사항 보완
   - Phase 6-11 우선순위 재조정
   - 전체 일정 재확인
